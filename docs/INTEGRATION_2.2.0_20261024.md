## Объединённое поведение

- Восстановление отсутствующего состава использует нативные Train/Carriage, сохранённые ID, общий груз, расписание и положения, включая выгруженные и портальные представления. Поезд с тем же ID либо загруженное представление оригинала препятствуют запуску. Путевой граф служит проверкой конфликта, мир и прошлые действия состава не перематываются.
- Возврат отсутствующих представлений существующего неизменного вагона остаётся отдельным действием; его координатор не потерян при слиянии. Отмена, выход администратора и остановка обслуживают оба координатора.
- Груз поездов адресуется по постоянному ID вагона и общему хранилищу, а не по UUID временного тела. Смена представления и выгрузка тела не должны делать неизменный груз недоступным для связанного отката.
- В GUI добавлены подготовка и подтверждение восстановления состава. Действующие проверки OP/AuthCore сохраняются.
- Просроченные предпросмотры полного состава включены в общий сборщик `PreviewMaintenance`; тяжёлый payload не удерживается до следующего открытия GUI или выхода игрока.
- Контрольные точки поездов создаются на границах загрузки/выгрузки, с объединением повторов. Проверки категории поезда и lifecycle выполняются до постановки в очередь и до полного снимка. Периодического сканирования содержимого поездов не добавлено.
- Проверки масок Create выполняются до копирования грузов и состояния активатора. Общий тик контроллера учитывает все семь нативных ID стационарных контроллеров.

Ранние классы `CreatePlayerConsumption`, `CreateDeployerPlayerRestore`, `CreateDeployerActorState` и сопутствующие consumption-mixin не включены повторно: более поздняя линия уже реализует эти направления через `CreateHumanRestore`, `CreatePlayerProgress`, расширенный inventory runtime и JointFormat 6. Возврат формата к 4 либо раннего общего запрета смертельных действий отменил бы более новые проверенные контракты. Исходная история остаётся доступна в родительской ветке.

## Проверки

Точные результаты и ревизии фиксируются после фактических запусков. Успешный выход Gradle без `AVILIX_CREATE_SMOKE_OK` не считается успешным игровым прогоном.

Обязательные проверки этого объединения: Java 21 compile; AsyncPipeline и Create preflight; нативные восстановление состава, смена/выгрузка представлений и груз; прежние структурные и активаторные операции; GUI-команды; истечение предпросмотров; live-маски; запуск без Create. Новый набор включает двенадцать сценариев состояния полного состава поверх прежних сценариев разборки и восстановления представлений (48 всего).

### Найденный отказ портального восстановления

Первый прогон CI прошёл на трёх профилях и отклонил нативный NBT в `state-portal` на `current-fd132`. Локальный исходный прогон и 32 повтора одного состояния прошли. Детерминированное воспроизведение: поменять местами два корректных элемента `EntityPositioning`; прежнее сравнение отвергает их на `Native.Carriages[0].EntityPositioning[0].Cutoff`. Нативный `Carriage.write` выгружает `entities.entrySet()` HashMap, а `read` восстанавливает map по ключу измерения: порядок списка не является состоянием вагона.

Снимки и проверка восстановления теперь упорядочивают только `EntityPositioning` по `Dim`. Все элементы и все вложенные поля сохраняются, дубли/некорректные измерения по-прежнему отклоняются валидатором. Добавлены восстановление переставленного снимка и отрицательные проверки изменения `Cutoff` и `PositionAnchor` после staging; перед внесением порчи тот же endpoint проходит `ready()`. Нативный целевой прогон: 48 сценариев, успешно. Полная матрица после исправления проверяется отдельно.

## Открытые границы

- Перемотка портального перехода уже существующего переместившегося состава остаётся отдельной задачей. Восстановление отсутствующего состава не объявляется этой перемоткой.
- Произвольные внешние эффекты модов и командные функции наград не получают поддержку от одного слияния веток. Действующие безопасные отказы сохраняются.
- Возврат AI ограничен принятыми пользователем 256 последними смертями текущего запуска; это согласованная граница, не новая незавершённая задача.
- Полный актуальный модпак, авторизованный production-путь и сравнение MSPT/retained heap остаются открытыми. Предыдущие локальные измерения без действующей авторизации AuthCore не доказывают снижение показателя Observable для фермы с 8 пилами и 8 активаторами.
