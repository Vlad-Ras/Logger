## Обязательное поведение

- Logger должен минимизировать собственную работу в серверном потоке и работу других модов, которую вызывают его перехваты, снимки и запросы capability. Низкий размер heap не считается доказательством низкой нагрузки.
- Чтение живого мира, сущностей, инвентарей, capability и нативный сериализатор мода выполняются в серверном потоке. Перенос этих вызовов на CPU-worker создаёт гонки; отделённые данные обрабатываются в фоне.
- SNBT/JSON-кодирование, сравнение снимков, форматирование, построение планов, поиск, сортировка, файловые операции, сетевые запросы и БД выполняются вне серверного потока, когда входные данные уже отделены. Фоновое задание не должно удерживать Player, Level, Menu или mutable ItemStack вместо снимка.
- Нет дополнительного ticking модов, сброса/переэкипировки их содержимого, отправки игровых действий или принудительной загрузки чанков ради наблюдения. Подписки на штатные события предпочтительнее опроса.
- Проверка отключённой категории происходит до снимков и обходов содержимого. Повторный модовый сериализатор после его ошибки не вызывается; неполный снимок не заменяется фиктивным полным NBT.
- Применение и компенсация откатов бюджетируются по тикам. Их фактическая цена, включая дорогостоящий единичный вызов мода, проверяется отдельно.
- Не снижать нагрузку скрытым удалением событий, ресурсных дельт, обязательных снимков или проверок AuthCore/OP.

## Сделано в этом проходе

1. Один вызов `BlockEntity.saveWithFullMetadata` вместо цепочки повторных reflective save после ошибки. Возвращается отделённая копия либо явное отсутствие снимка. Счётчик ошибок ограничен.
2. Проверка server thread и уже загруженного чанка до чтения блока/capability. Закрытие удалённого меню не загружает чанк ради журнала. Сериализатор сущности также не запускается в фоне.
3. Обход кликов при отключённой категории контейнеров начинается до чтения игрока/меню; пакет с чужим containerId не запускает захват.
4. Счётчики диагностики не удерживают неограниченное число UUID конструкций/координат механизмов. Переполнение сводится в счётчик `[other]`; сам журнал не теряет строки.
5. Задание разниц контейнера не захватывает `MenuAction` и через него Player/Level/Menu. Проверка байткода синтетического lambda-метода входит в regression.
6. Анализатор JFR schema 2 различает `server_execution_samples_logger_self`, `logger_called`, `wrapped_simulation`, `unattributed`. Вызванный Logger сериализатор относится к `logger_called`; обычный тик мода ниже `avilixlogger$withSource` — к `wrapped_simulation`. Это классификация сэмплов по стеку, не точное измерение времени каждого вызова.

## Существующее ограничение насыщения

27.10.2026 [исправлена задержка неполной journal-пачки при насыщении](JOURNAL_PRESSURE_2.2.0.md): writer публикует её после опустошения уже принятой очереди, не дожидаясь flush timer. Обычные уведомления больше не отменяют retry backoff БД; устранён lost wakeup sender, проверка видимости прекращает поиск после первого файла. Контрольный старый writer воспроизводит дефект; новый проходит disk/replay и настоящую ClickHouse. Это исправление отдельной задержки, без обещания устранить ресурсное насыщение.

`WeightedQueue.put` использует блокирующее противодавление. При переполнении CPU/event/journal очереди producer, включая серверный поток, может ждать. Вынесение обработки в фон само по себе не решает это ограничение. Безграничная очередь, синхронное кодирование на сервере или незаметная потеря событий не добавляются. Дальнейший способ обработки длительной перегрузки должен проверяться вместе с ограничениями памяти и сохранностью журнала; гарантировать отсутствие задержек при произвольно долгом отказе БД сейчас нельзя.

Реальные авторизованные замеры полного модпака ещё не получены. Нельзя объявлять исчезновение прежних ~60 000 мкс/тик в Observable по одному CI smoke.

Gift-аудит использует существующий queued packet callback и native запись одного boolean. Проверка отключённой категории идёт до чтения IPayloadContext. Полный GiftSavedData и неограниченное множество UUID получателей не сериализуются. Дополнительных тиков, инвентарных/capability обходов, SavedData lookup или сетевых рассылок нет. Native-тест при отключённом production capture проверил ровно одно исходное исполнение/context read на пакет. Это структурная проверка границ работы, а не production-бенчмарк MSPT/ОЗУ.

## Дополнение: меню групп коробок

Привязка к реальному BE из ChestMenu выполняется один раз при подтверждённом открытии. Logger не вызывает BlockPack.clusterAt, не обходит соседние коробки и не повторяет выбор группы. Проверяются уже загруженный чанк, серверный поток и идентичность BE. Снимки/разницы используют фактическое хранилище; дополнительные тики и world reads в CPU-worker не добавлены. Это структурное ограничение работы, не новый замер MSPT/heap.

## Дополнение: состояния BlockPack и БД

Проверка rollback-critical для BLOCK_INTERACT использует готовые before/after у фонового ClickHouse writer. Дополнительных world reads, вызовов модовых сериализаторов, перехватов или опроса по тикам не добавлено. Сохраняется содержимое уже захваченных изменений. Случай after-only не превращается в mandatory heavy detail. Объём БД для исправленных состояний вырастет относительно ошибочно пустых detail-строк; это ожидаемая сохранность, а не замер нагрузки.

## Дополнение: тексты Supplementaries и ванильных табличек

Supplementaries packet scope начинается в уже существующем server executor после фильтрации, не на common-pool этапе. До первого native acceptClientMessages нет BE-снимка; wax/claim отказ не запускает сериализатор. Для двух указателей before общий, после callback один after. Категории/AuthCore/server thread проверяются до снимка и повторно перед записью. ThreadLocal вне активного packet scope не вызывает native serializer; Player/BE не передаются worker. Нет дополнительного tick polling, capability обходов, вызова native permission checks, сетевых действий или загрузки чанков.

Общий SignTextAudit теперь учитывает отключённые категории 1/2 до собственного снимка и повторно перед after. Create joint observers сохраняются отдельно. Сбой sign observer не повторяет оригинальный setter и использует ограниченную диагностику. Native тесты и сырой контракт подтверждают границы работы, не численную экономию MSPT/ОЗУ. Положительная авторизованная публикация и прежнее блокирующее противодавление очереди остаются открытыми.

## Дополнение: Create display targets Supplementaries

Новый адаптер использует native выбранные BE/holder/book; не повторяет target getter и reservation checks. Read-only predictor исключает собственные NBT snapshots для заведомого no-op, учитывая raw/filter и native resolved reset книги. При antique ink или остановке по reservation возможна консервативная пара снимков. Нет tick polling, owner registry или capability поиска; одна свободная Frame на потоке очищает все live ссылки, nested close проверен отдельно. SNBT остаётся у worker.

Общее ядро отката теперь выставляет restoring на время записи и компенсации, предотвращая аудит собственного восстановления. Проверка BE type до изменения блока предотвращает лишние native onRemove и потерю/дублирование инвентаря при несовместимой истории. Это не обещание подавить произвольные эффекты всех сторонних модов и не численный MSPT/heap результат. [Состав, доказательства и ограничения](SUPPLEMENTARIES_DISPLAY_COMPATIBILITY.md).
