# AvilixLogger 2.1.30

«Запись событий → Обработчики» содержит 361 переключатель. Поиск работает по моду, названию и постоянному имени обработчика. Состояние применяется без перезапуска и хранится в данных мира. Номера прежних категорий сохранены. Протокол 12 требует одинаковой версии на сервере и клиенте.

Разрешение обработчика действует вместе с его категорией. Вложенный обработчик может независимо записать своё событие. Изменять настройки могут администраторы. Служебные проверки, блокировки и полные снимки жизненного цикла Create продолжают работать. При пропуске грузового действия или работы актора периодный откат через неполную историю блокируется.

| Путь из Observable | Изменение |
| --- | --- |
| Промышленный ItemStackHandler при отказе, симуляции и повторной установке того же стека | Симуляция сразу проходит в нативный вызов. В остальных случаях захват сравнивает отделённые значения. NBT предметов, жидкостей и состояния блока создаётся при фактической мутации. Исходные время, источник и полный набор полей до и после сохранены. |
| Вложенные item, fluid и settings callbacks | Один промышленный снимок уже содержит изменение этих полей. Вложенный перехват не создаёт второй полный снимок. |
| Внешние capability Create | Убрана повторная копия уже отделённого стека. Подготовка NBT по-прежнему ждёт подтверждения связи передачи со штуковиной. |
| Рефлексия при подборе предмета и обработке урона | Используются прямые API 1.21.1 для задержки подбора, количества тиков и текущего урона. |
| Очередь и пробуждение потоков | Готовность сигналится ожидающим потребителям с учётом уже накопившейся работы. Сигнал завершения требуется только при ожидающем читателе или поставщике. Сохранены ограничения по памяти, резервации и порядок. |

Standalone-проверки очереди прошли. В сценарии с четырьмя потребителями обработано 20 000 записей без потерь и дублей. После завершения число занятых мест и вес полезной нагрузки равны нулю. Тесты игрового API проверяют сериализацию настроек, сохранение старой маски, пустые попытки вставки, корректное содержимое до и после извлечения.

Профиль всего модпака и прирост TPS требуют замера до и после на сервере. Отчёт Observable включает штатные вычисления Create и AE2, поэтому его суммарное время по механизмам нельзя целиком отнести к Logger.
