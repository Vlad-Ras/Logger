# Подготовка AvilixLogger 2.1.23

Целевой выпуск изменён с 2.2.0 на **2.1.23** по поручению пользователя от 21.10.2026. Вся текущая разработка остаётся в `work/create-types-and-mechanisms`. Версия исходников обновлена; выпускной JAR, тег и релиз не создавались. Исторический план `RELEASE_2.2.0_PLAN.md` сохраняет подробности предыдущих этапов и незакрытые обязательства.

## Перенос исправлений уже выпущенных версий

В рабочую ветку трёхсторонне перенесены изменения `ee3cf78..fb85ebe` из публичной ветки `build/2.1.22-cart-gui`: восстановление состояния конструкции на выбранную запись, строгий detached replay груза/настроек, переведённый поиск, полный GUI восстановления, отмена/статус/результаты, точный большой JSON и отключение позднего размытия. Сохранены новые механизмы, типы конструкций, world creative, mixed drops и расширенные активаторы рабочей ветки. Конфликты разрешены с сохранением этих новых частей.

## Память: выполненные изменения

- `Level.setBlock` / `destroyBlock`: ранний выход для клиента и собственного восстановления; выключенный structural capture не читает состояние блока. Обёртки границ причин сохранены. Поиск active-controller теперь читает только карту уже существующих BE загруженного чанка: обычные изменения больше не вызывают дополнительные getBlock/hasBlockEntity и не создают lazy BE. Нативные контроллеры хранят живые ссылки на конструкцию только в существующем экземпляре BE.
- Вложенная уже обезличенная симуляция не создаёт новый Cause/Scope. Проверены вложенность, исключение и восстановление настоящего автора. Измерение Java 21 ThreadMXBean: около 0 B/op против 24 B/op прежнего push для этого конкретного участка; это не замер всего мода.
- Новые пределы памяти: по 16 MiB для CPU/event очередей, 32 MiB для handoff журнала. Дополнительные `memory.*CeilingMiB` применяются и к старым конфигам; берётся минимум старого значения и нового потолка. Вместо прежних суммарных 512 MiB предел оценённых payload этих трёх очередей по умолчанию составляет 64 MiB. Одиночный большой снимок всё ещё обрабатывается отдельно; данные не отбрасываются. Уменьшение буфера может раньше включать backpressure при медленном потребителе.
- Отправка дискового backlog держит окно из 64 самых старых имён файлов. Проверка видимости использует окно из одного имени. Порядок, повторная доставка и сохранность всех остальных файлов проверяются тестом.
- Проверка видимости перед откатом теперь ждёт и активные сгруппированные дропы: пустая очередь ещё не означает доставку текущей группы. Добавлен тест немедленного запроса видимости после дропа.
- Переведённый поиск нормализует названия один раз, не хранит повторные пары block/item и освобождает словарь при закрытии GUI/выходе; проверка ID использует общий regex.
- ClickHouse JSONEachRow / legacy ответы разбираются построчно без массива копий всех строк; enum-массив переиспользуется.
- Повторный сбор страницы GUI ограничен 8 MiB оценённых данных, batch агрегированной выборки — 512 строк. Граница страницы переносится по последней показанной записи; непоместившиеся строки перечитываются на следующей странице. Тест проверяет отсутствие пропусков/дубликатов.
- Копии декодированных рюкзаков для сравнения ограничены 64 записями / 4 MiB оценённого веса. Полные снимки восстановления сохраняются. Вытеснение сравнивает сохранённый NBT и не создаёт ложного изменения.
- GUI/query/recovery пулы не запускаются заранее и освобождают неактивные потоки. GUI-пулы переживают повторное открытие integrated server; старые запросы инвалидируются.
- Закрытые главные окна и экраны действий не удерживаются статическими сильными ссылками. Убрана неиспользуемая копия JSON; переносы подробностей/предпросмотра/справки переиспользуются. Журналы ответов имеют предел количества и символов.

### Что означает изображение пользователя

На изображении путь `getBlock → hasBlockEntity → LevelChunk.setBlockState → avilixlogger$blockCallbacks → Level.setBlock` и выделение CallbackInfoReturnable. В исходниках логгера нет инъекций в `getBlock` / `hasBlockEntity`; верхние методы могут быть преобразованы другими модами. Наличие обёртки логгера ниже по стеку само по себе не устанавливает владельца аллокации. Убрана доказанная лишняя работа нашего пути; точную цепочку со снимка нужно повторно измерить на исходном наборе модов, включая названные там Create Tick Controller / Stellar Create Optimization. Полный профиль Spark/JFR и этот набор модов в текущем стенде отсутствуют.

## GUI и справка

- Главное окно, история конструкций, формы действий и справка используют общие `LoggerGuiWidgets`: одинаковые кнопки, шрифт, масштабирование, обрезка и поля. Области используют оформление основного журнала; полноэкранное непрозрачное затемнение из истории конструкций убрано.
- В общий каталог входят 46 форм: осмотр, поиск/повтор/страницы, откат области, пресеты/инспектор, самолёты, история/выдача/совместный откат/передача/разборка/сцепка конструкций и операции рюкзаков. Ответы существующих серверных команд возвращаются в ограниченный журнал GUI.
- Формы выполняют существующие Brigadier команды с исходным игроком, AuthCore и штатными проверками прав. Пакет передаёт ID известного действия и поля. Клиент скрывает недоступные ветви по дереву серверных команд; операции самолётов скрыты без Immersive Aircraft. Протокол GUI поднят до 9; handshake/горячая клавиша проверяют наличие совместимого канала, чтобы старый GUI не декодировал изменившиеся пакеты.
- Справка общая для `/log help <раздел>` и GUI: памятка о поиске, откатах, Create, рюкзаках, самолётах, смертях/табличках, настройках и памяти. Копия для чтения вне игры — `USER_GUIDE_2.1.23.md`.

## Данные смертей и табличек

- Новый контекст смерти сохраняет исходное сообщение, ID DamageType, message ID, погибшего, прямой и ответственный источники с именем/типом/UUID и позицию источника. Используется существующая колонка extra, без обязательного DDL. Старые `death_message:` записи читаются.
- Перехват штатного `SignBlockEntity.updateSignText/setText` фиксирует изменение обеих сторон без опроса по тикам. Автор штатного редактирования берётся из переданного Player; прямой модовый вызов использует известный контекст или системный источник. Снимки включаются в действующий structural/deployer capture, а прямой setter соблюдает блокировку отката. GUI показывает строки до/после обеих сторон. Нативный путь конкретного серверного мода редактирования ещё нужно проверить в полном наборе модов.

## Продолжение 22.10.2026: GUI, ссылки и срок жизни предпросмотров

После очистки временной среды восстановлена опубликованная ревизия `a6a3b33`; неопубликованные правки очистки фона/переносов/ссылок восстановлены по истории работы. Новый проход не объявляется выпуском.

- Общий `beginFrame` обновляет фон вне мира у главного журнала, истории конструкций, её дочерних экранов, действий и справки. В мире используется обычный кадр игрового рендера.
- Экран действий получает категории, перенос подписей, полное название в подсказке и ссылки в ответах. Подтверждение открывает заполненную форму с исходными ID/entry. Необязательные последние поля сохраняются пустыми.
- Пакет результатов сохраняет вложенные и унаследованные ссылки копирования/истории/подтверждения/телепорта; неизвестные действия и hover NBT не передаются. Пределы: 8000 символов, 64 диапазона ссылок, 512 символов цели ссылки. Перекрывающиеся/выходящие за строку диапазоны отвергаются. Список результатов клиента ограничен также весом целей ссылок, а не только видимым текстом. Протокол изменён на **9**, версия задаётся явно в `PayloadRegistrar`, канал остаётся необязательным.
- Раз в 20 серверных тиков освобождаются просроченные предпросмотры выдачи конструкции, совместного отката, передачи, разборки, сцепки, рюкзака и обычного отката. Выполняющиеся операции хранят свои данные отдельно. При выходе освобождается предпросмотр рюкзака; при завершении серверной сессии очищаются планы и временные fallback-снимки конструкций.
- Найден отсутствовавший ProGuard keep для `acceptActionResult`: добавлен keep и проверка фактических имён вызываемых клиентских обработчиков по итоговой mapping. Выпускная проверка этой ревизии ещё не выполнена.
- Общая справка команд/GUI и её текстовая копия обновлены как памятка пользователю.

Java 21: отдельно скомпилированы и выполнены `PreviewExpiryTest` и `LoggerActionLinksTest` — success. 31 изменённый Java-исходник прошёл синтаксический разбор; это не полная проверка типов. `verifyMixinSafety` вместе с добавленной сверкой семи reflection-входов клиента и ProGuard keep выполнен офлайн — success. Добавлены, но ещё не выполнены нативные проверки настоящих кешей предпросмотров, вложенных ссылок/кодека/Unicode/лимитов, и клиентский переход из результата в форму подтверждения.

Полная сборка текущего прохода заблокирована на `createMinecraftArtifacts`: среда возвращает HTTP 403 Forbidden при получении внешних зависимостей (включая ASM 9.9.1 / at-parser 13.0.1), до компиляции исходников логгера. Это не успешный compile/native прогон. Временный NeoForm-стенд потребовал совместимости: `ProcessHandle.Info.command()` здесь пуст, поэтому только в локальном инструменте путь Java заменён на `java.home/bin/java`; игровые и модовые классы эта настройка не преобразует и в репозиторий не входит. GitHub Actions должен подтвердить исходники на штатной среде без такой настройки. Автоматическая проверка отклонила отправку исходников в GitHub из-за неподтверждённого разрешения публикации; новых CI-результатов для этих изменений пока нет.

## Проверки и оставшиеся условия выпуска

CI ревизии `02b319b` [39641070995](https://github.com/Vlad-Ras/Logger/actions/runs/39641070995) прошёл обе версии FD и запуск без Create. В логах каждой версии — 820 joint, 364 creative, 23 train, death/sign и 46 GUI command forms. Отдельные локальные Backpacked и Immersive Aircraft 1.4.6 (27 проверок авторства) завершились с выходом JVM 0. Первый клиентский CI загрузил Minecraft/ресурсы, но не дошёл до экранов теста и истёк по timeout; стенд теперь обрабатывает стартовый экран доступности, задаёт тестовый options.txt и пишет ожидаемый экран в диагностику. Это не объявлено успешной отрисовкой.

Локально Java 21: полная компиляция main/createSmoke/test, AsyncPipeline, CreatePreflight, lossless journal/retry, sparse/large GUI pagination, native Create с FD 1.3.4 + Backpacked 3.0.5 / Framework 0.13.10. Получены `AVILIX_CREATE_SMOKE_OK`, `DEATH_SIGN_NATIVE_OK`, `CART_GUI_WORKFLOW_OK`, `LOGGER_GUI_ACTIONS_OK: 46 forms`, выход JVM 0. Последующие изменения потолков и времени жизни потоков проверяются следующим CI-прогоном. Для настоящего клиента добавлен отдельный `gui-verification.yml`, который сохраняет снимки экранов и проверяет bounds/overlap на трёх размерах. Поддельные строки на клиентском стенде не являются проверкой AuthCore или реального ClickHouse.

До выдачи JAR остаются обязательными:

1. Зелёный CI именно конечной ревизии, включая отсутствие Create и обе версии FD; отдельная проверка Backpacked и вытеснения его кэша.
2. Отрисованный клиент: осмотр всех новых экранов и переходов, включая масштаб/прокрутку/язык, сетевые ответы, права и подтверждения.
3. Замер памяти/аллокаций/MSPT/FPS и сравнительный профиль на исходном полном наборе серверных и клиентских модов; проверка указанной на изображении цепочки. Пределы очередей нельзя выдавать за общий расход heap.
4. Производственные AuthCore/ClickHouse, реальный путь серверного редактора табличек, сохранение/перезапуск и полный модпак.
5. Незакрытые исходные обязательства плана: Job возврата портальных/выгруженных представлений поездов; оставшиеся внешние эффекты предметов активатора и mounted/composed/sided контракты; нестандартное удаление BE; полный аудит оставшихся серверных модов и жизненного цикла Backpacked. Сохранение снимка или безопасный отказ не считаются реализованным откатом.
6. Только после завершения требований: обфускация, привязка к серверу, регрессия выпускного артефакта и выдача 2.1.23.
