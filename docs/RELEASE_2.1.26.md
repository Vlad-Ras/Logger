# AvilixLogger 2.1.26

Minecraft 1.21.1, NeoForge, Java 21. Сборка с прежней обфускацией и штатной
проверкой AvilixAuthCore. Включает накопленную реализацию из веток 2.2.0.

## Изменения

- Операции контейнеров: точное добавление/извлечение по слотам, количество
  до/после, предмет с компонентами, подтверждённый блок и его координаты.
  Вторая половина составного контейнера имеет собственный адрес.
- Люк опыта Enchantment Industry: направление передачи, фактические mB,
  опыт до/после, подключённый блок хранения и отдельная позиция люка.
- OPAC: история claim/unclaim, время, инициатор отдельно от владельца,
  измерение и чанк; переход из GUI к безопасному месту в центре чанка.
- Журналы модов используют прежний интерфейс и общие компоненты оформления.
  Те же интеграции доступны в «ТИП». Выбор времени — отдельные поля «С / По»,
  быстрые периоды, часовой пояс и проверка введённых значений.
- Действия и результаты новых команд доступны в GUI. Нажатие кнопки не
  отправляет её ответ в чат. Доступ сохраняется только у администраторов.
- Исправлена потеря снимка «до» в таблицах сущностей/предметов/игроков.
  ClickHouse получает недостающие колонки через ADD COLUMN IF NOT EXISTS;
  существующие записи не удаляются, номера старых ActionType не меняются.

## Защита TPS при перегрузке

По выбранной пользователем политике серверный захват не ждёт свободного
места в заполненной очереди. При переполнении, слишком большом задании или
длительной конкуренции за внутреннюю блокировку новый захват останавливается.
Уже принятые worker-задания продолжают обработку и запись.

Остановка видна в заголовке GUI, отчёте производительности и серверном логе.
«Действия → Производительность → Возобновить захват» разрешает продолжение
после освобождения очередей. Интервал пропуска сначала принимается в журнал
отдельной записью CAPTURE_GAP. Без этого захват не возобновляется.
Счётчики заданий и проверок не выдаются за точное число игровых событий.
Старые интервальные снимки открытых меню не проигрываются через пропуск;
новый интервал начинается со следующего действия или открытия меню.

Это защита от ожидания ёмкости очереди, а не обещание нулевой стоимости
логирования. Внутренняя блокировка очереди имеет бюджет tryLock 200 мкс;
планировщик JVM/ОС может увеличить фактическую длительность вызова.
Данные очередей ограничены оценкой payload, а не полным heap JVM.

## Установка и проверка на рабочем сервере

Заменить прежний JAR Logger одним `avilixlogger-2.1.26.jar` на сервере и
администраторских клиентах. Существующие AuthCore, его ключ, конфигурацию
ClickHouse и каталог `avilixlogger-spool` сохранить. Частные моды и ключи
в этот JAR не включаются.

После штатного запуска открыть «Действия → Производительность → Проверить
запись в базу». Проверка требует настоящего разрешения AuthCore и прав
администратора. Она создаёт одну явно служебную запись, читает её подробности
и строку GUI по ID. Игровой мир, настройки механизмов и соединение хранилища
ради проверки не перезапускаются. Одновременно выполняется одна проверка.
Ответ появляется в GUI; задержка HTTP ограничивается настройками подключения.

Команды для консоли имеют те же формы в GUI: `/log perf`, `start`, `stop`,
`resume`, `check`. Начало замеров не возобновляет остановленный захват.
Проверка доставки также не снимает аварийную остановку.

## Границы проверки

Функциональная проверка доставки в реальном AuthCore-окружении и A/B/A
замеры полного модпака требуют рабочего сервера пользователя: отдельного
разрешённого стенда нет. Они не заменяются синтетическим тестом очереди,
native fixture без авторизации или программным OpenGL на CI. Пока нет
таких измерений, отсутствие регрессии MSPT/heap/GC/клиентского кадра на полном
модпаке не считается доказанным.

Адрес интерфейса виртуального хранилища не объявляется адресом внутренней
ячейки AE2. Полное покрытие всех взаимодействий каждого мода не следует из
переноса накопленного кода. Известная ошибка ручной остановки перезарядки
Scguns 1.5 воспроизводится также без Logger и не исправляется этим релизом.
