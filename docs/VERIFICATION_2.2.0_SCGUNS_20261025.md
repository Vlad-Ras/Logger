# Проверка Scorched Guns для Logger 2.2.0 — 25.10.2026

Проверенная ревизия: `3c343c250baf084c27b4cf6de06263b9b399640e`. Production-код совпадает с `dc3d8f06df9ffe2c02f12a744e1f09c39791510b`; последующая ревизия расширяет только тест миграции ClickHouse.

## Локальные проверки

Компиляция основного кода и native-fixtures, `testAsyncPipeline`, `testCreatePreflight`, `verifyMixinSafety`, `testExactModpackPreflight`, `verifyObfuscatedJar` завершились успешно. Raw preflight проверил 153 контракта, в том числе 9 Scguns; прочитано 99 классов из предоставленных JAR. Это проверка ABI, а не доказательство всех конфликтов после трансформации.

Проверены:

- неизменяемость оружия и позиции выстрела, запись/сжатый журнал/чтение, отрицательные дробные координаты, yaw/pitch/eyeY;
- отказ на неполных, нечисловых, недопустимых и неизвестных версиях данных; отсутствующая позиция не заменяется нулевой;
- точный ID в SQL, source-фильтр, запись/чтение контекста shot/hit/kill/reload/player-death при отключённых необязательных деталях;
- сохранение actor погибшего в PLAYER_DEATH и отдельная запись убийцы WEAPON_KILL;
- маски категорий и отказ универсального частичного отката оружейных событий;
- наличие стабильных интерфейсов, внедряемых в чужие классы, в обфусцированном JAR; отсутствие встроенных классов Scguns, Framework и Curios.

## Native-стенд

NeoForge 21.1.244; настоящие предоставленные Scguns 1.5, Framework 0.13.11, Curios 9.5.1, GeckoLib 4.9.2. Использовался созданный для теста мир и локальный listener 127.0.0.1. Сначала пройден Scguns без corefix, затем расширенный прогон вместе с `avilix_scorchedguns_corefix` 1.0.0. Финальный production-код проверен с corefix.

Маркер результата: `SCGUNS_NATIVE_OK`.

Native-проверка подтвердила применение optional hooks, настоящий принятый выстрел и отказы cooldown/отмены/пустого оружия, дробовик с 26 дробинами на один GunFireEvent.Post и луч без сущности-снаряда. Настоящий native damage source вызвал положительный LivingDamageEvent.Post и смерть ServerPlayer; native перенос боезапаса изменил реальное оружие. Выполнены save/load снаряда и native teleport с точными координатами и углами.

Отдельные ядра формирования записи проверены на перемещённом стрелке и сменённом оружии: исторические данные сохраняются, actor/target не меняются местами. Новые ServerPlayer-fixtures имели штатную spawn-защиту: только её таймер в тестовой жертве установлен в 0. Авторизация Logger при этом не изменялась.

На стенде **нет AuthCore**. Проверено, что live capture отключён: `accepted=0`, `adapterFailures=[]`. Native-поведение и формирование отделённых DTO не выдаются за проверку авторизованной публикации в production. Полный цикл реальной перезарядки через двух клиентских игроков, все виды оружия и переход по GUI на авторизованном сервере остаются отдельной приёмкой.

В локальном контейнере NFRT не определял путь Java через ProcessHandle. Отдельная локальная копия инструмента исправляла только две операции определения Java executable; исходный артефакт, моды, авторизация и код сервера не менялись. CI использует официальный неизменённый инструмент независимо от этого локального обхода ограничения среды.

Для повторения native-прогона положить Scguns/Framework/Curios/GeckoLib и, при необходимости, corefix в отдельную директорию. Не подставлять весь архив модпака:

```sh
./gradlew runServer -PscgunsSmoke -PscgunsSmokeMods="$SCGUNS_SMOKE_MODS" \
  -Pneo_version=21.1.244 -PcompatCreateVersion=6.0.10-281 \
  -PcompatAe2Version=19.2.18 -PcompatFrameworkVersion=1.21.1-0.13.11
```

Native-fixture намеренно требует неавторизованный тестовый стенд и самостоятельно останавливает созданный сервер после проверки. Production-мир для такого запуска не используется.

## CI

[Серверные регрессии и ClickHouse](https://github.com/Vlad-Ras/Logger/actions/runs/40207173779), [GUI](https://github.com/Vlad-Ras/Logger/actions/runs/40207173836).

Все четыре серверных профиля (`current-fd132`, `current-fd134`, `logged-pack`, `client-s4-core`), отдельная настоящая ClickHouse-база и GUI завершились успешно. В серверных профилях Scguns отсутствует: они дополнительно подтверждают безопасную optional-загрузку и регрессии существующих интеграций, а не заменяют локальный native-прогон Scguns.

Проверка настоящего ClickHouse 24.8 сначала создала split-таблицы, воспроизвела старую схему без be_after для сущностей/предметов/игроков и открыла новый экземпляр хранилища. После миграции проверены пять видов оружейных событий, дробные позиции/углы, точный ID и повторное открытие базы. Маркер: `CLICKHOUSE_NATIVE_OK: old split schema migration`.

## Границы результата

Функциональный контракт описан в [SCORCHED_GUNS_COMPATIBILITY.md](SCORCHED_GUNS_COMPATIBILITY.md). Полная совместимость 267 JAR, все взрывы/турели/ловушки, поздний огонь без исходного damage source, производственный AuthCore/ClickHouse, полная клиентская перезарядка и переход через GUI ещё не объявляются принятыми. Новых измерений MSPT/heap на боевом сервере или ферме 8 пил + 8 активаторов + portable storage interface этот прогон не содержит; прежние 60 000 мкс/тик Observable не объявляются устранёнными.
