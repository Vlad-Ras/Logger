# AE2: отмена ссылки CPU и потеря связи с заказчиком

29.10.2026. Продолжение [прямой отмены CPU](AE2_CPU_CANCEL_COMPATIBILITY_2.2.0.md). База `25103b5cd441f472e510cf50721f84bc1dd56ab2`; ветка `work/2.2.0-ae2-link-cancel-20261029`. Проверенный код `fa9584ee8e9099ed174cc692ffcba4834ff58aae`, tree `68214e204aa4fdccdd18558d0cf4abae9a5f18e0`. Выпускной JAR не создаётся.

## Закрываемые пропуски

Прямой ICraftingLink.cancel на CPU link выставляет canceled до последующего CPU cleanup, поэтому прежние finishJob(false) и nexus guards намеренно пропускали такую отмену. Новый CraftingLinkMixin наблюдает сам cancel до изменения флага. Принимается только настоящий CraftingLinkAccess с CPU, совпадающим текущим job link; done/canceled, requester-only link и чужой/устаревший job отклоняются. Server-thread и прежние Logger/AuthCore/category/logAe2 guards действуют до native чтения. Запись подтверждается только по canceled прежнего link без done. Исходный Operation вызывается один раз, исходное исключение сохраняется; подтверждённый переход перед ошибкой получает NativeThrew.

Новая запись использует ME_CRAFT_CANCEL, source ae2:crafting:cancel, настоящий JobId, full key/ITEM и исходный planned long output, CPU address/bounds/dimension/name. CancellationOrigin=cpu-link и StateTransition=cpu-link-cancelled отличают этот путь. Сам факт вызова API не устанавливает автора: без известного синхронного UI источника actor нейтральный.

Чтобы обычная CPU/UI отмена не создавала второй снимок и строку на вложенном link.cancel, существующий CPU scope отмечает владение текущим захватом одним boolean полем. Оно устанавливается только при наличии разрешённого CPU capture, восстанавливается в finally; повторный CPU/link capture выходит до metadata/key снимка. Меню сохраняет прежнюю временную ссылку и атрибуцию игрока. Nexus по-прежнему пропускает CPU link с уже выставленным raw canceled. После прямой link отмены последующий CPU cleanup также видит canceled и не создаёт повторную строку. ThreadLocal, реестр jobs и дополнительные тики не добавлены. Положительный production append/dedup с AuthCore остаётся отдельной приёмкой; ниже проверяются native predicates и data-only scopes.

При исчезновении requester link прежний nexus capture требовал обе стороны и не мог записать штатную отмену сохранившегося CPU. Теперь при request=null и доступном текущем CPU job источник — сам CPU. Сохраняется RequestLinkMissing=true, прежний native JobId и planned output. Запись подтверждается по canceled nexus и CPU link без done; отсутствующая сторона не разыменовывается. При наличии requester остаются прежние проверки обеих links и совпадения UUID. Потерянный адрес/игрок не восстанавливаются эвристикой, точная причина expiry в запись не выдумывается. Details объясняет отсутствие связи и привязку строки к процессору; для прямой ссылки есть отдельная читаемая подпись.

## Десять реальных автономных заданий

Стенд сохраняет Interface/Crafting Card → Pattern Provider → vanilla Blast Furnace → bottom Import Bus. Каждый job рассчитывает и запускает native InterfaceLogic; нет подмены планов, links, CPU NBT или ручного ticking AE2. Прежние семь card/requester/nexus/UI/CPU/logic/fault случаев сохранены. Добавлены три отдельных JobId:

| Случай | Native действие и ожидаемые данные |
| --- | --- |
| CPU link API | Прямой CPU link.cancel после отправки 2 raw iron в печь; neutral CPU row, исходный planned 2 ingots, paired links canceled, tracker освобождён |
| Link и ошибка | Transformed link wrapper вызывает injected Operation без изменения аргументов, ровно один раз; настоящий native cancel выполняется перед тем же исходным Throwable; row получает NativeThrew |
| Потерянный requester | Уничтожается единственная известная dev IGridConnection заказчика. Настоящий grid split вызывает native removeNode и убирает requester из nexus. После штатного grace/expiry AE2 отменяет CPU job; row neutral, CPU address, RequestLinkMissing. Затем связь восстанавливается через GridHelper |

В третьем случае до split реальный Import Bus получает diamond filter: возврат результата заблокирован на время ожидания expiry, сама печь тикает штатно. Crafting card удаляется уже после native detach, предотвращая новый запрос на отделённой сети. После отмены и reconnect фильтр снимается, проверяются все 2 stock ingots; начальное условие двух raw inputs не применяется повторно после ожидания. Её старый link уже не связан с CPU nexus; отмену CPU выполняет штатный AE2 expiry. Fixture ждёт обычные серверные тики, не вызывает isDead/cancel вручную, не меняет tickOfDeath и не ускоряет таймер. После восстановления связи уже отправленные ингредиенты штатно дают ровно 2 Interface stock ingots, без нового crafting job/ложного CPU finish. Это конкретный real grid-split/missing-requester путь; остальные topology/unload случаи этим не объявляются проверенными.

У десяти data-only rows девять нейтральных actor и один UI player. Три прежние linked rows адресованы requester, остальные — CPU. Running/no-transition fault, done, idle, repeat, requester-only link, disabled/off-thread poison inputs и вложенный capture owner дают пустой результат. Десять rows проходят двухэлементную AsyncLogStorage очередь с byte limit, FIFO, full ITEM, JobId, planned amount, ordered failure markers и RequestLinkMissing, затем Gzip/LogText/details. Настоящий rollback kernel сохраняет applied=0/skipped=1: job receipt не возвращает ресурсы и не пересоздаёт заказ.

Controlled-plan fixture отдельно вызывает настоящий standalone CPU link.cancel для fluid planned 5 000 000 000, сохраняет full key/neutral actor/CPU address и проверяет отсутствие второго capture при CPU cleanup. Native cleanup затем вызывается CPU API; это не ручной tick и не полноценный fluid recipe route. Число controlled-plan rows сохраняется 14 (5 accepted/5 rejected/4 cancelled). Pure worker/journal/Gzip и настоящая ClickHouse расширены CPU-link и missing-requester details, Long.MAX_VALUE/full fluid key, neutral actor, CPU/JobId, typed feed/details, minimal mode и повторным подключением.

Первый source commit `ac0b45d81bf9e8bb718682573b832ab99df0dca5` не прошёл [native основной этап](https://github.com/Vlad-Ras/Logger/actions/runs/40883720935): parent processing timeout, CPU idle, 2 cell ingots/0 Interface stock. В коде стенда оставалось условие двух raw inputs для повторного входа в recovery, хотя печь продолжала работу; возврат результата также не был удержан до expiry. Это были дополнительные ошибки ожиданий, но корневую причину тайм-аута установил следующий прогон. Исправление `b689f96` меняет только два dev fixture: начальный dispatch отделён от recovery, Import Bus блокирует возврат до отмены/reconnect, timeout получает вложенный mode/phase. Production hooks не менялись между этими ревизиями. Вторая ревизия `b689f96` тоже завершилась [timeout](https://github.com/Vlad-Ras/Logger/actions/runs/40885457252): cancelMode=9/phase=1/detached=true, nexus canceled=true/done=false/requestMissing=true, CPU idle, оба ingots удержаны в furnace output. Диагностика установила основной дефект стенда: общий isActive guard родителя прекращал вызовы child fixture при намеренном отключении requester, поэтому recovery вообще не исполнялся. `fa9584e` переносит только phase=11 dispatch перед этим guard; production код снова не меняется. Оба неуспешных прогона не засчитываются в acceptance.

Raw preflight добавляет CraftingLinkMixin к согласованному optional набору: теперь 16/17 групп для 19.2.12/19.2.18. Сохраняются проверки cancel сигнатуры, req/cpu/canceled/done fields, CPU → logic → finish(false) → link и native setCanceled(true) перед nexus.cancel; существующие negative contract tests покрывают отсутствие/несовместимость этого метода до применения нового mixin.

Production не добавляет обходов world/grid/inventories/capabilities, forced chunks, job map, Future waits или tick subscriptions. Одна bounded ссылка меню и boolean ownership живут на CPU, scope восстанавливается в finally; live key/координаты читаются только на сервере, detached SNBT/JSON/journal/БД идут через прежний worker. Новые корректные строки увеличивают историю, byte accounting/backpressure сохранены. Численный выигрыш MSPT/heap/latency не заявляется.

Открыты потерянный CPU или недоступный finalOutput, исчезновение обеих сторон, прочие network/unload/topology callbacks, причины expiry за пределами наблюдаемых фактов, pause/resume history, другие requesting machines/addons/fluid/multi-output recipes и virtual ME rollback. Положительный production AuthCore → hook → ClickHouse → GUI, весь transformed модпак с configs/scripts, rendered remote terminal, Scguns 1.5 manual stop и A/B/A MSPT/heap/GC фермы 8 пил + 8 активаторов с саженцами + portable storage interface остаются в приёмке.
