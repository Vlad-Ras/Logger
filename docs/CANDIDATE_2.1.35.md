# AvilixLogger 2.1.35 — тестовый кандидат

Minecraft 1.21.1, Java 21. Проверенная среда исправления зависимости — NeoForge 21.1.259, Create 6.0.10, AE2 19.2.12 и дополнительные моды стендового Create-набора. Это кандидат для проверки на копии сервера; финальный выпуск не объявлен. Актуальный модпак/конфиги пользователя и положительная штатная авторизация на нём пока не проверены. AuthCore требуется штатный, его проверка не отключалась.

Файл сборки — `avilixlogger-2.1.35.jar`; внутренняя версия мода — 2.1.35. Нужен соответствующий клиентский JAR для GUI. Исходники и описание версии находятся в отдельной ветке `work/2.1.35-crash-recovery`.

Контрольная сумма: [CANDIDATE_2.1.35.sha256](CANDIDATE_2.1.35.sha256). Исходные проверки этапов 1–10 выполнялись на NeoForge 21.1.265. Исправление для установленной у пользователя NeoForge 21.1.259 описано в [отдельном отчёте](VERIFICATION_2.1.35_NEOFORGE259.md). Сборка по умолчанию и минимальная версия запуска теперь 21.1.259; параметр версии стенда не меняет минимальную версию автоматически.

## Изменения относительно 2.1.34

1. Добавлена отдельная форма восстановления построек после краша, с подтверждением до применения.
2. Явно разделены «Состояние на момент» и «Изменения за период»; обычный откат отменяет события после выбранного момента, replay повторяет события периода с включёнными границами.
3. Дата/время задаются отдельно; показан серверный часовой пояс. Передаются абсолютные UTC-моменты, неоднозначное время DST без offset не принимается.
4. Добавлены интервалы 5/30/60 минут и сутки, выбор радиуса/WorldEdit/блока под прицелом и игроков.
5. Предпросмотр crash replay проверяет текущий мир без изменений и без WAL; после подтверждения выполняются повторные проверки. Историческая оценка не выдаётся за live-проверку.
6. Координатор больше не ждёт неопределённо `event.hasTime()`: crash replay и обычный откат используют свои бюджеты.
7. Для crash replay выделены операции/время на тик, загрузки чанков и лимит одновременно удерживаемых чанков. Полные чанки готовятся до мутаций, тайм-аут сообщает причину.
8. Блоки сцены восстанавливаются совместно: резервирование области, резервные снимки всей постройки, состояния, NBT/слоты, проверка результата, общая компенсация при ошибке.
9. Полные зарегистрированные Block Entities восстанавливаются со снимками NBT и инвентарей; неизвестные/неполные/противоречивые данные вызывают отказ. Ошибка сериализации сообщает координаты и тип.
10. Замена контейнера не выбрасывает старое содержимое; снимается прежний BE перед заменой состояния. Дроп защищённых объектов во время сцены не выдаётся.
11. Проверяются двери, кровати, двойные сундуки и опоры; физические общие инвентари учитываются по адресам, без двойного подсчёта.
12. Отложенные тики жидкостей/падающих блоков и случайные тики защищённой области не вмешиваются в незавершённую сцену. Старые и новые поддержанные capability-обработчики тоже резервируются.
13. Поддержанные сущности и пассажиры участвуют в общей сцене с блоками. UUID проверяется в живых измерениях и сохранённых регионах; неподтверждённые ресурсные/модовые деревья отвергаются.
14. Crash replay имеет долговечный undo-WAL с версией, SHA-256, fsync и атомарной публикацией. Незавершённая сцена компенсируется при новом запуске до игровых тиков; commit/квитанции запрещают повторную выдачу завершённых событий.
15. Добавлены принудительные сохранения до/после, с возвратом исходных флагов автосохранения при завершении/ошибке/отмене. Это не резервная копия и не ускоритель.
16. Предметы всей сцены проверяются по точной идентичности и количеству. Неподтверждённое изменение общего запаса не применяется; проверка выполняется на worker с лимитом памяти и отменой.
17. Добавлены связанные доказательства штатных переносов между игроком и ванильным контейнером, включая курсор. Они позволяют завершить перенос в блоке, когда конечный инвентарь игрока уже сохранён. Онлайн-игрок резервируется; офлайн `.dat` читается без изменения.
18. Новые подтверждения переноса привязаны к сохраняемому периоду записи. Отключение типов/обработчиков, изменение capture-конфигурации, потеря авторизации, пауза очереди и собственные откаты/выдача отзывают прежний период.
19. Отзыв выполняется один раз на операцию; detached-preview и точная WAL-компенсация отделены от обычных подавленных мутаций. Пустая остановка Create не отзывает историю.
20. Исправлена цепочка состояний A → B → A: одинаковые начало/конец больше не скрывают промежуточное сохранённое состояние B.
21. Для обычных баков Create добавлен баланс жидкости всей сцены с точными компонентами, ёмкостью и полным набором частей. Контроллер учитывается один раз. Креативные/паровые баки и неподтверждённое изменение общего объёма не применяются.
22. Подготовка ждёт видимости принятых строк истории вне Server thread. Повторные положительные ID дедуплицируются; фильтр игрока не скрывает разрыв общей истории.
23. Фазы/прогресс поступают в исходный GUI/чат с ограничением частоты. `/log replay details [страница]` показывает ID, координаты/UUID и причины отказа.
24. В меню скачивания логов добавлена кнопка открытия клиентской папки `avilixlogger-server-logs` существующими виджетами GUI.
25. Добавлена выгрузка `logs/collision-forensics/diagnostics.log` с сохранением подпапки на клиенте; остаются ограниченные части, проверка ссылок и доступ администратора. Произвольные серверные пути не принимаются.
26. В ClickHouse добавлены обязательные поля связанных снимков игрока/контейнера в BLOCKS с аддитивной миграцией и чтением. Добавлены регрессии обфускации/миксинов для проверенной NeoForge 21.1.265.

## Границы кандидата

Запись инвентарей игроков этим кандидатом не выполняется. Производственные преобразования, жидкости/энергия непрозрачных модовых хранилищ, ещё не поддержанные сущности/attachments и полная совместимость актуального модпака остаются открытыми. Отказ до изменений предпочтительнее неподтверждённого восстановления ресурсов. Наличие NBT само по себе не подтверждает ресурсную операцию.

Сохраняемая метка не подтверждает сессии вообще без Logger, внешние изменения мира/БД и произвольную подмену файлов. Полная приёмка на сервере пользователя не заменяется стендовыми результатами.

## Проверки кандидата

Компонентные/HTTP/миксин/обфускация, native Create и работа без Create, совместные блоки/сущности/игрок, перезапуски и новый сценарий баков проверяются в отчётах [этапа 9](VERIFICATION_2.1.35_STAGE9.md) и [этапа 10](VERIFICATION_2.1.35_STAGE10.md). Перед выдачей тестового файла отдельно проверены сеть, серверные тики, реальный GUI/FPS, наблюдаемая память и освобождение больших снимков; точные измерения и ограничения находятся в отчётах. Это не подтверждение производительности всего модпака с онлайном.
