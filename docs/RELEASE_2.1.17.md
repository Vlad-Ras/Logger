# AvilixLogger 2.1.17 — поиск GUI и заполнение страниц

Выпуск основан на 2.1.16 и сохраняет исправления 2.1.12–2.1.16. Новая разработка Create из ветки 2.2.0 в этот JAR не включена.

- Поле времени принимает `13.10.2026 03:00`, `13.10.2026`, `03:00` (сегодня), ISO-дату и диапазон `12.10.2026..13.10.2026`. Прежние периоды `30m`, `2h`, `7d` сохранены. Начало включительно; отдельная дата в конце диапазона включает весь день.
- Используется часовой пояс сервера, которым журнал подписывает строки. Он передаётся при открытии GUI и указан в подсказке. Неверная дата/время не заменяется молча периодом по умолчанию.
- Поле «Поиск» теперь входит в запрос; клиент больше не скрывает неподходящие строки уже полученной страницы. Ищутся сохранённые имя игрока, идентификаторы, источник/текст и русское название действия. Ввод применяется кнопкой или Enter.
- Имя поезда, владелец/название самолёта, блок, категория и источник включены в SQL до LIMIT. Пустое скрытое поле самолёта не влияет на остальные категории. Обычная страница запрашивает только размер страницы + одну запись для кнопки «Далее».
- Для группировки записи добираются до заполнения страницы, конца истории или защитного предела 32000 записей. Курсор строится по последней показанной записи/группе; следующая страница не пропускает проверочную запись.
- Запросы БД, разбор старого сжатого журнала, фильтрация и подготовка страниц выполняются в GUI workers. Очередь ограничена; устаревшие запросы отменяются. На серверном потоке остаются короткая проверка прав/контекста, снимок позиции, обновление состояния страницы и отправка результата. Нулевую суммарную нагрузку это не обещает.
- Старый unified-журнал хранит сжатый JSON: поля внутри него нельзя искать через JSONExtractString по base64. Этот совместимый путь сохраняет SQL-фильтры времени/позиции/действия и добирает совпадения в фоне. При превышении 32000 записей/30 секунд возвращается явная ошибка с просьбой сузить поиск. Ошибка современной схемы не снимает выбранные фильтры.
- Сетевой протокол GUI обновлён до 4: для новых функций установить 2.1.17 на сервер и клиент. Клиентская установка остаётся необязательной для обычной игры; авторизация AuthCore не изменена.

Проверки:
- Полная компиляция Java 21, прежняя AsyncPipelineTest и новые проверки дат/часовых поясов/DST, длительностей, редких совпадений, полного заполнения, курсоров, отмены, группировки и рабочего потока.
- HTTP fixture: фильтры/экранирование до LIMIT в feed/split; поиск названия действия; запрет снятия фильтров при ошибке схемы; страницы старого сжатого журнала с точным ID конструкции.
- 16 native проверок codec и production query builder, повторены на обфусцированном 2.1.17 с Create/Aircraft и без них.
- Прежний полный `AVILIX_CREATE_SMOKE_OK` с 41 сценарием PSI/контейнеров/воронок пройден на исходных классах 2.1.17.
- На обфусцированном JAR: 43 проверки tick wrapper/авторизации, 34 проверки атрибуции и 7 проверок декодирования/oversized stacks.
- Все классы предыдущего 2.1.16 и конфигурации mixin сохранены; исходники авторизации, атрибуции, NBT/предметного декодирования и контекстов тика не менялись. Manifest/mod metadata содержат 2.1.17, тестовый AuthCore и fixtures исключены.

Реальный авторизованный ClickHouse, полный серверный модпак, отрисованный клиентский GUI и Spark/MSPT на рабочем сервере не проверены. HTTP fixture проверяет контракт запросов, а не план выполнения реальной БД.
