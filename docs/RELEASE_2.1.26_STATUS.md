# AvilixLogger 2.1.26 — подготовка и приёмка

Дата: 02.11.2026. **Статус: 2.1.26-dev, к установке на рабочий сервер не принят.**

## Состав

Основа — `38c3794` из последней локальной ветки покрытия модов, включая
`d327b6e` (Corpse/Accessories) и `991981d` (OPAC/FTB Teams). Незакоммиченный
промышленный пакет сохранён отдельным коммитом `8561958` до новых правок.
Проверены головы всех 29 опубликованных веток `work/2.2.0*`: каждая входит
в историю этой подготовки. Это сохранение накопленной реализации, а не
заявление о полном функциональном покрытии всех модов. Новые поезда и ранее
исключённый портал в объём не добавляются.

## Изменения

- Предметные контейнеры: записи на изменённый слот, точное частичное
  добавление/извлечение, количество и полный предмет до/после. Для native
  InvWrapper и CompoundContainer сохраняются диапазоны слотов с адресами
  физических контейнеров. Изменение второй половины не приписывается первой.
  Адресные метаданные не меняют сравнение состояния при откате старого снимка.
- Остальные capability-хранилища: известный адрес интерфейса явно отличается
  от подтверждённого физического контейнера. Внутренний адрес виртуального
  хранилища не выдумывается. Полное распределение по всем ME cells и произвольным
  составным capability ещё не доказано.
- Люк опыта Enchantment Industry 2.4.2: наблюдается конкретный native handler,
  который уже выбрал мод. Сохраняются блок подключения, его координаты и
  измерение, координаты люка, направление и фактически возвращённое количество
  жидкости, содержимое баков до/после и опыт игрока до/после. Полный инвентарь
  игрока ради этой операции больше не копируется. Адрес подключения не
  объявляется внутренним физическим распределением общего бака.
- OPAC: сохранены native claim/unclaim и их подтверждённое авторство из
  контекста пакета/команды/отложенной задачи. Инициатор и владелец — разные
  поля; отсутствие автора не заменяется UUID владельца. В подробностях видны
  операция, владелец до/после, чанк и измерение.
- `log entrypos <entryId>` и кнопка TP используют сохранённую запись.
  Для claim выбран центр чанка; загрузка запрашивается только явным переходом,
  без блокирующего ожидания чанка. Запрос ограничен 200 тиками, собственный
  ticket освобождается при завершении/отмене/остановке. Перед переходом
  повторно проверяются права и соединение. Неизвестная позиция и глобальные
  настройки не превращаются в переход к нулевым координатам.
- Новая команда и прежние `combatpos source/view/target` имеют формы в GUI.
  Ответы, включая отложенные, идут через исходный CommandSource в результаты
  GUI. GUI-источник не рассылает ответы администраторам в чат.
- Время: форма «С / По» с отдельными датами и временем, быстрые периоды,
  указанный часовой пояс, строгая проверка календаря и включение всей верхней
  минуты/секунды или дня. `0m` означает поиск с начала журнала.
- «Моды» открывает отдельный экземпляр привычного журнала с закреплённым
  фильтром интеграции. Те же пресеты добавлены в «ТИП». Сохранены общие
  компоненты оформления, детали, результаты, масштабирование и права.
- «Действия → Производительность»: отчёт, начало и остановка замеров,
  включая текущие/пиковые размеры и ожидания всех трёх очередей. Ответы
  остаются в GUI. [Методика и ограничения](QUEUE_DIAGNOSTICS_2.1.26.md).

## Устранённая лишняя работа

Убран добавленный промышленным пакетом обработчик каждого тика всех Create
SmartBlockEntity. Отложенный сброс планируется после реального изменения.
Промышленные данные создаются лениво, а не для каждого SmartBlockEntity.
Сравнение отделённых снимков ModStateAudit выполняется в CPU worker; живые
объекты мира и native сериализация по-прежнему читаются только на сервере.
Поиск пресета и регулярное выражение сводки не создаются заново для каждой
строки. Поправлена обнаруженная при первой компиляции ошибка типа меню
DieselAudit. Эти изменения не являются численными замерами TPS/heap/FPS.

  testAsyncPipeline, testCreatePreflight, verifyMixinSafety,
  verifyObfuscatedJar. Проверены Create 6.0.11-313 / AE2 19.2.12 и целевые
  Create 6.0.10-281 / AE2 19.2.18; подробные задачи указаны в локальных журналах.
- RELEASE_UI_CONTRACTS_OK: календарь, часовой пояс, обратный диапазон,
  включённая верхняя минута/секунда, целый день, стабильные ID модов.
- STORAGE_UI_EVIDENCE_OK: частичные количества, нейтральное авторство,
  направление claim/unclaim, отрицательные чанки, запрет неизвестных позиций.
- AVILIX_CREATE_SMOKE_OK: прежний native Create/груз/восстановление/GUI workflow.
- STORAGE_BLOCK_ADDRESS_NATIVE_OK: реальный второй контейнер, частичное
  извлечение 4 → 2, точный адрес и ID блока в деталях, применение старого
  снимка без новых адресных метаданных.
- OPAC_STATE_NATIVE_OK: native создание и снятие тестового привата,
  конкретный владелец и чанк. Это проверка данных и мутаций, а не разрешённая
  production публикация журнала.
- Raw preflight официальных OPAC 0.33.0, EI 2.4.2, Diesel Generators
  1.21.1-1.3.15 и Create 6.0.10-281: 16/19/31/10 mixins в четырёх группах, 131 прочитанный
  target class. Пропущенные отсутствующие моды не засчитываются проверенными.
  Официальные артефакты не объявляются побайтно равными пользовательским JAR.
- CART_GUI_CLIENT_OK: настоящая клиентская отрисовка истории, действий,
  результатов, справки, формы времени, выбора модов и OPAC-журнала;
  границы и пересечения элементов проверены на 320×240, 640×360 и 960×540.
  Повторный прогон включает длинный отчёт производительности в GUI. Fixture
  сохраняет отдельный итоговый статус и пишет ошибку через штатный logger,
  чтобы один успешный exit code клиента не подменял результат проверок.
- Exact preflight исходных архивов: 313 mixin-контрактов в 18 группах,
  217 классов из предоставленных JAR; core проверен по runtime Minecraft.
  Включены Accessories, Cobblestone, Vibrant Vaults и FTB Teams. Ни одна из
  этих групп не пропущена как отсутствующая. Это raw bytecode, без запуска
  полного модпака и без доказательства отсутствия transformed-конфликтов.
- Исходные архивы содержат два варианта bf_blockpack и побайтно одинаковые
  дубликаты i_architecture. В отдельном каталоге для raw preflight выбран
  ранее указанный пользователем no-auto-glass-v2 и одна копия i_architecture.
  Исходные архивы сохранены, Lithium `.disabled` не включался. Частные JAR
  в репозиторий и CI не добавлялись.
- Синтетический QueueLoadProbe: три раунда по 100 000 записей без потери и
  нарушения порядка; p99 put 5.689–11.157 мкс. При удержании consumer на
  100 мс producer ожидал 100.348 мс. Это не MSPT/FPS и не полная стоимость
  логирования; риск backpressure подтверждён экспериментом.

Для запуска в этой среде использованы отдельные локальные копии Java 21 и
Gradle. Локальная копия NeoForm изменяет только два определения пути Java
при недоступном ProcessHandle.command. Оригинальный инструмент не изменён.
Код Minecraft, чужие моды и AuthCore не подменяются. UI использует программный
OpenGL; это не измерение FPS на компьютере пользователя.

## Блокеры выдачи релиза

1. Нужен положительный путь с рабочим AuthCore: hook → worker → journal →
   настоящая ClickHouse → повторное подключение → GUI. На локальном стенде
   авторизация закономерно отключила рабочую публикацию. Это ограничение
   сохранено и не обходилось ради теста.
   В восстановленных исходниках AuthCore отсутствует штатный dev-mode:
   разрешение требует server-private-key.pk8 на разрешённом сервере.
   Исходники не содержат ключа. Приёмку нужно выполнять на таком стенде;
   передавать секретный ключ в чат или репозиторий не требуется.
2. Нужны сопоставимые A/B/A замеры на полном согласованном модпаке и его
   конфигурации: без Logger / исходный Logger / кандидат; MSPT p50/p95/p99,
   allocated bytes, heap после GC, длительные GC/очереди, клиентский frame time.
   Отдельные сценарии: закрытый и открытый idle/action AE2 терминал, ферма
   8 пил + 8 активаторов с саженцами и portable storage interface, массовые
   операции хранилищ/OPAC, длинная история и запросы GUI.
3. Очередь WeightedQueue остаётся ограниченной и без потери принятых записей,
   но при насыщении использует backpressure. Блокирующее ожидание производителя
   существует в коде; отсутствие задержек server thread при перегрузке не
   подтверждено. Нельзя одновременно объявить это устранённым и не проверить.
4. Не закрываются прежние пункты полного модпака: Scguns 1.5 manual stop,
   остальные непроверенные контракты модов, произвольные виртуальные storage,
   все варианты энергии/опыта и их реальные источники. Полное покрытие
   автоматически не следует из перенумерации версии.

Релизный 2.1.26 и утверждение «нагрузки нет» до этой приёмки не выдаются.
