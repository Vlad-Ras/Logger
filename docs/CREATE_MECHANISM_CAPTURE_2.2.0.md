# Create: отдельные настройки записи механизмов

Изменения для 2.2.0 от 04.11.2026. Основа: `1542e2cb6b56b932b359fe717c20a64e3d94fe77`.

В окне **«Запись событий»** добавлены отдельные переключатели:

| Тип | Область |
| --- | --- |
| Активаторы | Действия и обмен предметами активаторов на штуковинах; общие события стационарных активаторов |
| Буры | Действия буров на штуковинах; общие события стационарных буров |
| Пилы | Действия пил на штуковинах; общие события стационарных пил |
| Комбайны | Действия комбайнов |
| Плуги | Действия плугов |
| Катки | Действия катков |
| Желоба | Обычные и умные желоба |
| Воронки | Андезитовые и латунные воронки, включая варианты на конвейере |
| Переносные интерфейсы | Предметные и жидкостные интерфейсы |
| Раздатчики на штуковинах | Ванильные dispenser/dropper в качестве механизмов Create |

Настройки сохраняются в мире и применяются немедленно; доступ и проверка ревизии остаются прежними. Старые 12 номеров не меняются, новые используют номера 13–22 и по умолчанию включены. Это настройки будущего сбора, а не фильтры поиска. Общие настройки `createCapture.logActorWork`, `logCargoTransfers`, `logLifecycle` и переключатель типа самой штуковины продолжают действовать.

## Стоимость отключённого захвата

Обёртки native `MovementBehaviour.visitNewPosition`, `tick`, `onSpeedChanged` подавляют захват на время отключённого механизма и восстанавливают состояние в `finally`. Сам native callback выполняется. Прямые observers активатора и его обмена предметами также проверяют настройку до снимка руки/цели/инвентаря. Общие события, setBlock, происхождение дропа и cargo observers не должны обходить подавление. На стационарных машинах область ограничена tick исходного Create block entity; обычные действия игрока с блоком продолжают логироваться.

Нет новых периодических полных снимков, фонового чтения мира или обхода инвентарей. Существует небольшая стоимость проверок и один короткий маркер пропуска на вагонеточную штуковину для каждой последовательности жизненного цикла/смены настроек. Это не обещание конкретного прироста TPS: ферма пользователя требует отдельного сравнения Spark/JFR.

## Восстановление и пропуски

Переключатель отдельного механизма не отключает сборку, упаковку, установку, разборку и удаление самой штуковины. Полные снимки сохраняют её блоки, NBT и груз. Восстановление из полного снимка после работы отключённого механизма остаётся доступным при включённых настройках самой вагонеточной штуковины и `logLifecycle`.

Незаписанные внешние изменения нельзя отменить. Отмена периода и восстановление актуального состояния через воспроизведение дельт останавливаются на маркере пропуска, вместо выдачи неполного состояния за актуальное. Более поздний полный снимок позволяет восстановление без пересечения пропуска. Если отключить всю категорию вагонеток или `logLifecycle`, новые полные снимки тоже не будут сохраняться — эти общие выключатели не изменены.

## Владелец активатора

Сессия активатора уже определяла владельца, но строка события принудительно получала `SYSTEM` и пустой UUID. Теперь используется найденный владелец: сохранённый Owner активатора, иначе Owner вагонеточной штуковины. Имя берётся из онлайн-профиля, сохранённого имени владельца вагонетки или UsernameCache; крайний запасной вариант — UUID. Сохраняются source механизма, адрес, construction ID и owner source.

Главная строка активатора и строки обмена его руки с грузом используют владельца только внутри точной сессии активатора. Общая политика FakePlayer и нейтральный CauseContext не изменены. Неизвестный владелец, посторонний FakePlayer и несвязанные серверные операции остаются SYSTEM. Вложенное действие настоящего игрока сохраняет его собственную личность.
