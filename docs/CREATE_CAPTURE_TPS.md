# Управление нагрузкой Create на TPS (AvilixLogger 2.1.23)

Система захвата работает только на сервере и уважает обязательную авторизацию AvilixAuthCore. Настройки добавлены в **COMMON** конфигурацию `config/avilixlogger-common.toml` (в зависимости от запуска имя и расположение конфигурации определяются NeoForge). Для гарантированного применения выполните перезапуск сервера после редактирования файла.

## Рекомендуемый режим, если множество вращающихся штуковин просаживает TPS

```toml
[createCapture]
    # Отказ от аудита вращающихся конструкций на обычном/часовом подшипнике.
    # Механизмы Create продолжают работать, но новые действия этих
    # конструкций не логируются и не смогут быть откатаны через Logger.
    logBearings = false

    # Остальные виды штуковин продолжают логироваться.
    logMinecarts = true
    logTrains = true
    logOtherContraptions = true

    # Категории. Ниже все оставлены включенными для остальных видов.
    logActorWork = true
    logCargoTransfers = true
    logLifecycle = true
    logMovement = true
```

Все параметры по умолчанию равны `true`, чтобы при обновлении **не исчезали ранее регистрировавшиеся события**. Установите `logBearings = false` вручную — это главный переключатель для указанной проблемы.

| Параметр | Что отключает при `false` |
|---|---|
| `logBearings` | аудит сущностей-конструкций Create bearing/clockwork: обработку типизированного тика, распознавание работающих механизмов, грузовые снимки, события жизненного цикла и структурные снимки контроллера |
| `logMinecarts` | аудит вагонеточных штуковин Create |
| `logTrains` | аудит типизированных сущностей вагонов и поездов Create; часть независимых поездных событий имеет свои обработчики |
| `logOtherContraptions` | аудит поршней, шкивов, портальных подъёмников, лифтов и стабилизированных конструкций |
| `logActorWork` | специализированную запись действий работающих на штуковинах буров, пил, активаторов, сборщиков и подобных механизмов |
| `logCargoTransfers` | дорогостоящую запись перемещений предметов/жидкостей и автоматизации на движущихся конструкциях Create |
| `logLifecycle` | сохранение состояния сборки, выгрузки, удаления и разборки конструкций |
| `logMovement` | телеметрию движения и статуса вагонеточных штуковин |

**Важно:** фильтрация типов событий не равна отключению стороннего мода. Содержимое мира и сами механизмы Create не меняются. Записи до изменения конфигурации сохраняются. Откат не может восстановить *новые*, сознательно исключённые из аудита изменения. События другого происхождения (например, самостоятельное действие игрока, другие моды, отдельно испускаемые события поезда) могут продолжить логироваться согласно общим настройкам `[capture]`. Защитные блокировки выполнения отката не отключаются.

В обработчиках на горячем пути фильтр стоит **до NBT/снимков блоков/контейнеров**, а в контексте тика отключённого Create-контрапшена используется источник `minecraft:simulation`, чтобы общая атрибуция `mod:create` не порождала ложные дорогостоящие записи.

## Как измерить результат

Измерьте Spark profiler на одном и том же мире/количестве подшипников, с тем же количеством чанков, нагрузкой и игроками:
1. До переключения: MSPT p50/p95/p99, время `EntityTickSourceMixin`, `AbstractContraptionEntityMixin`, `CreateMechanismAudit`, `ServerLevelSetBlockMixin`.
2. Измените `logBearings = false`; перезапустите сервер.
3. С тем же количеством вращающихся конструкций повторите профиль.
4. Убедитесь, что альтернативные механизмы (поезда, вагонетки), ClickHouse и авторизованные откаты сохранённых событий работают корректно.

Проверка FPS/ОЗУ не заменяет сравнения MSPT. Не делайте откат на живом сервере без резервной копии и подходящего тестового стенда.
