# Контракты предметов активатора Create

Контракт охватывает одну связанную операцию руки, груза, блоков и сущностей. Работает прежний путь `/log cart undo-transfer <ID конструкции> <ID записи>` → `/log cart confirm-transfer`. Владелец конструкции остаётся отдельным полем; автоматический исполнитель — SYSTEM.

## Поддерживаемые реализации

| Реализация | Проверенная версия поставщика | Возвращаемые эффекты |
| --- | --- | --- |
| Create: обычная и красная наждачная бумага | 6.0.11 | Вход, результат, расход бумаги, инвентарь и runtime |
| Create: шоколад, сладкий рулет, шоколадные ягоды, медовое яблоко | 6.0.11 | Питание, насыщение, эффекты, расход и прогресс получателя |
| Create: чай строителя | 6.0.11 | Питание, спешка и бутылка в руке либо инвентаре |
| Create: картонный меч | 6.0.11 | Отбрасывание, замедление цели, скорость и спринт технического игрока |
| Модовая еда с точным vanilla-классом `Item` | Minecraft 1.21.1 | Стандартное потребление и поддерживаемые эффекты из FOOD-компонента |
| FD: точные классы `ConsumableItem`, `DrinkableItem` | 1.3.2 и 1.3.4 | Потребление, питание, посуда в руке/инвентаре/дропе, Nourishment |
| FD: точные классы `MilkBottleItem`, `HotCocoaItem` | 1.3.2 и 1.3.4 | Фактически снятый эффект и бутылка, без повторного случайного выбора при возврате |
| FD: точные классы `MelonJuiceItem`, `PopsicleItem` | 1.3.2 и 1.3.4 | Лечение и тушение, остаток предмета |

Для еды допускаются ванильные эффекты и конкретная реализация `farmersdelight:nourishment`. Другой модовый эффект требует своего адаптера. Общий контракт обычной еды требует точного класса `net.minecraft.world.item.Item`: наследник с переопределённым поведением не получает его автоматически. Картонный меч допускает только его штатное зачарование отбрасывания.

Классы шести перечисленных предметных реализаций FD и `NourishmentEffect` побайтово совпадают в официальных JAR 1.3.2 и 1.3.4. Это не распространяет контракт на произвольные версии и наследников этих классов.

## Нативные правила Create сохраняются

Еда с FOOD-компонентом может передаваться настоящему игроку. Для напитка без FOOD используется нативный тег Create `deployable_drink`; сам логгер не дописывает туда предметы. Если напитка без FOOD нет в теге, обычное использование активатором действует на его технического игрока. Обычную еду технический игрок Create сам не ест: этот нативный отказ проверяется отдельно. Прямой FD finish-callback фруктового льда проверяет адаптер тушения отдельно от обычного DeployerHandler; правил Create логгер не меняет.

У чая строителя полная сумка получателя может привести к потере бутылки по коду самого Create; FD, напротив, может выбросить посуду. Снимок возвращает фактическую операцию, не изменяя правила выдачи посуды.

Наждачная бумага проверяется отдельно для штатной второй руки/предзагруженного компонента и настоящего server-level входа из мира. Пустой entity getter внутри Create ItemUseWorld остаётся нативным ограничением.

## Формат журнала и предохранители

`JointFormat=5` добавляет обязательный манифест `ItemContracts`/`ContractCount`. Для каждого использованного модового предмета сохраняются ID, точный класс реализации, тип эффектов, версия контракта и версия поставщика. План проверяется без живого мира; перед первой записью повторно проверяются зарегистрированный предмет, класс и версия установленного мода. Удалённый контракт, подмена реализации, повреждённый манифест и понижение нового модового действия до старого формата отклоняются.

В runtime руки дополнительно сохраняются скорость, спринт, горение и persistent data технического игрока. Старые форматы 1–4 сохраняют прежние ограничения и не получают новые предметные контракты задним числом. `JointFormat=6` дополнительно требует версионированный `External` для технического игрока и получателя; формат получателя — `Human.Format=2`. Форматы 1–5 не получают возврат внешних данных задним числом.

Для Backpacked 3.0.5 / Framework 0.13.10 известные ленивые пустые данные материализуются перед снимком. `JointFormat=6` возвращает unlock-наборы и данные штатных tracker, экипированные рюкзаки с компонентами/содержимым, legacy backpack, разблокированные слоты, выбранный рюкзак, косметику, cooldown бессмертия и масштаб. Используются штатные сериализаторы Framework и строгий обратимый кодек предмета; неизвестные tracker и потеря данных запрещены.

Дельта применяется по отдельным tracker, unlock-ID, слотам и ключам. Посторонние изменения других ячеек сохраняются; изменение затронутой ячейки после активации вызывает конфликт до первой записи. Проверяются версии, число ячеек/tracker, конфигурация слотов и точное повторное кодирование до применения. При замене экипировки требуется закрыть меню игрока. Штатный кеш BackpackInventory перепривязывается к восстановленным стекам; индекс и базовые снимки рюкзака обновляются без нового игрового события. Отмена возвращает те же затронутые данные вперёд вместе с остальными участниками действия.

Framework setValue, unlock-прогресс (включая прямые increment/read), содержимое нативного рюкзака, снятие/замена экипировки и пакеты настроек защищены резервациями участника. В обычном игровом пути проверка блокировок содержимого имеет быстрый выход без поиска держателя. Живые marker-интерфейсы подтверждают применение optional mixin до возврата изменённых данных. Неизменённые внешние ключи не переписываются, а неизвестные attachments продолжают давать неполную запись.

Произвольные командные функции наград, внешние attachments/глобальные реестры других модов, неизвестные эффекты, поводки и неподдерживаемые сущности не объявлены обратимыми этим контрактом. Их наличие в общем модпаке само по себе не означает проверенную интеграцию.

Возврат нативного AI ограничен 256 последними умершими поддерживаемыми животными текущего запуска; пользователь принял этот предел для 2.2.0. После вытеснения или перезапуска возврат запрещён до первой записи.

## Подтверждённая регрессия

Текущий контракт внешних данных: ревизия `42f19747fe13ecb3b62c47dca6e7a3271c5e22e6`, [GitHub Actions 39601030213](https://github.com/Vlad-Ras/Logger/actions/runs/39601030213) — success для FD 1.3.2/1.3.4 и Backpacked 3.0.5 / Framework 0.13.10. По **820** совместных и **364** creative-сценария; отдельный сервер без Create также прошёл. В нативных сценариях возвращаются unlock-прогресс FakePlayer/получателя и содержимое настоящего экипированного рюкзака. Проверены компенсация, ранние конфликты, независимые изменения, прямые increment, setValue, изменение содержимого и снятие экипировки под резервацией.

Предыдущая проверенная ревизия без возврата внешних данных:

Ревизия `96c0bab86606214bea6f775f314b717817fc0a39`: [GitHub Actions 39594140086](https://github.com/Vlad-Ras/Logger/actions/runs/39594140086). Оба отдельных сервера FD 1.3.2 и 1.3.4 с Backpacked 3.0.5 / Framework 0.13.10 выдали `AVILIX_CREATE_SMOKE_OK`: по 756 совместных сценариев и 364 creative-сценария активатора, включая MINECART, TRAIN, BEARING и OTHER. Компиляция, отделённые pipeline/preflight проверки и verifyMixinSafety также прошли; самостоятельный сервер без Create/Ponder/Flywheel выдал `CREATE_ABSENT_NATIVE_OK`.

Предыдущая матрица включала нативное кормление зарегистрированной поддерживаемой еды FD, напитки и посуду, отмену/компенсацию, конфликт состояния и два metadata-only барьера Backpacked. Эти два барьера заменены отдельным контрактом возврата в следующей ревизии. Прямой finish-callback фруктового льда и real-level sandpaper остаются отдельно обозначенными проверками контрактов, а не новыми возможностями штатного Create.
