# Подготовка AvilixLogger 2.2.0

## Активаторы: проверенный результат прохода 21.10.2026

Исходники находятся в отдельной ветке [work/create-types-and-mechanisms](https://github.com/Vlad-Ras/Logger/tree/work/create-types-and-mechanisms). Runtime-коммит **`aa6a301af10cfcd5b333f42eb97d5bd38abe8482`** прошёл [GitHub Actions 39554819937](https://github.com/Vlad-Ras/Logger/actions/runs/39554819937): `compileJava`, `compileCreateSmokeJava`, `testAsyncPipeline`, `testCreatePreflight`, `verifyMixinSafety`, общий `AVILIX_CREATE_SMOKE_OK` и самостоятельный `CREATE_ABSENT_NATIVE_OK`. Стенд: Java 21, NeoForge 21.1.219, Create 6.0.11. Версия разработки остаётся 2.1.11; релизный JAR 2.2.0 не выпускался, ветка не сливалась в master.

Реализованы прежние отсутствовавшие операции:

- **Кормление и напитки настоящего игрока.** Отдельный endpoint возвращает инвентарь всех 41 слотов и курсор меню, питание, эффекты, атрибуты, XP и изменённые cooldown. Для физического runtime используются невиртуальные методы базового `Player`: серверная сессия и измерение не загружаются через `Entity.load`. Сохраняются точные критерии достижений с наносекундами, статистика, рецепты, счётчики scoreboard и членство в командах. Награды повторно не выдаются. Откатываются изменённые действием счётчики/достижения; постороннее игровое время, достижения, рецепты и неизменённые действием attachments сохраняются. Проверены ожидание 20 нативных тиков, расширенный стек 1024, еда и молоко, удаление/возврат эффекта, отмена в разных фазах, конфликты затронутых данных и резервации.
- **Смертельный удар по известным животным.** Связанный снимок включает руку с дропом и расходом оружия, боевое состояние, собственные счётчики и членство цели в scoreboard-команде. Проверены живой труп и уже удалённая цель. Для возврата сохраняется именно нативный объект с его AI, навигацией и goal selector; новый моб из одного NBT вместо него не создаётся. Компенсация возвращает труп либо логическое отсутствие, не повторяя смерть и генерацию дропа. Возврат счётчиков команд учитывает их нативное удаление вместе с трупом.
- **Creative IO вместе с действием.** `JointFormat=4` содержит количество всех участников и ограниченный журнал изменений инвентаря на отдельных native-вызовах использования предмета. Проверяется баланс руки, конечного груза, creative выдачи/поглощения и расходования. Установка блока после выдачи из creative crate, изменение world/entity-цели, отмена и конфликты входят в один зарезервированный Job. Бесконечный шаблон проверяется, но не переписывается. Отсутствующий участник или квитанция расходования не принимается за полный снимок.
- **Расход наждачной бумаги.** Помимо native пути второй руки/предзагруженного компонента добавлен sparse endpoint входного `ItemEntity` для настоящего server-level вызова sandpaper. У Create 6.0.11 собственный `ItemUseWorld` имеет отдельный пустой entity getter: обычному активатору не добавлялось несуществующее нативное умение брать свободный предмет из мира. Проверка real-level sandpaper-контракта отделена от вызова обычного `DeployerHandler`.

Нативные матрицы: `CREATE_DEPLOYER_JOINT_NATIVE_OK` — **228** сценариев; `CREATE_DEPLOYER_CREATIVE_NATIVE_OK` — **364** сценария. Обе охватывают MINECART, TRAIN, BEARING и OTHER, успешные откаты, отмену/компенсацию, отказы до первой записи, потерю runtime, повреждение манифеста, конфликты количества/компонентов и блокировки. Прежние 320 creative transfer и 4 world creative сценария, структуры, сцепки, поезда, контейнеры, воронки и работа без Create также прошли общий CI. Локальный серверный прогон дополнительно выполнялся с AE2 и Backpacked/Framework; это не проверка полного серверного модпака.

**Существенные границы и оставшаяся работа:**

- Нативные объекты умерших поддерживаемых животных (pig/cow/sheep/chicken) удерживаются ограниченным кешем **256 последних целей текущего запуска**. **Пользователь принял этот предел как достаточный для 2.2.0 (21.10.2026).** После вытеснения или остановки сервера возврат по этой записи запрещён до любых изменений. Кеш очищается после остановки координаторов. Долговечное восстановление AI после вытеснения или перезапуска не входит в обязательный объём этого направления.
- Произвольные эффекты чужих модовых предметов, командные функции наград достижений, изменение внешних player attachments самим потреблением, поводки и другие неописанные связи требуют явного полного контракта. Такие действия остаются барьерами частичного отката. Универсальные адаптеры для этих эффектов не реализованы.
- Полный production-путь AuthCore/emit, настоящий ClickHouse, клиентский GUI, Spark/MSPT и обфусцированный выпуск этой ревизией не подтверждены. Остальные направления 2.2.0, включая жизненный цикл поездов при порталах/выгрузке, остаются отдельными задачами.

Таким образом, три прежних общих запрета заменены работающими совместными операциями в перечисленных границах. Ограничение возврата AI принято пользователем и больше не считается незавершённой работой для 2.2.0. **Функциональный остаток направления — контракты внешних модовых эффектов:** их отсутствие не заменяется количеством smoke-сценариев или проверенными отказами.

## Продолжение 20.10.2026: кормление игрока активатором

Проверен исходный `DeployerHandler.activateInner` Create для 1.21.1: при режиме USE и цели-игроке Create вызывает `stack.finishUsingItem(level, playerEntity)` для еды и для предметов с тегом deployable drink. Предыдущий smoke молока на техническом игроке этот путь не проверял. В логе успешное кормление теперь получает отдельный результат «кормление игрока» и категорию событий сущностей. Барьер неполного отката устанавливается **до** нативного вызова, чтобы при исключении после изменения игрока нельзя было принять запись за безопасную.

Откат кормления остаётся закрытым: текущая конечная точка `Target` использует `Entity.load` и не подходит для настоящего `ServerPlayer`; его инвентарь, статистика и достижения не входят в транзакцию. До разрешения отката нужен отдельный адресуемый endpoint игрока, проверки инвентаря/питания/эффектов/статистики до записи мира, компенсация этих данных и native испытания еды и напитка (включая отмену, исключение и конфликт). Простое добавление `minecraft:player` в список поддерживаемых сущностей небезопасно. Изменение этого прохода не выпускается без Java 21 компиляции и серверного прогона.

## Проверенный остаток по исходникам — 18.10.2026

Последние восемь коммитов `1501a8e`–`6a4e669` дорабатывают одни и те же два направления: мировой creative IO и смешанные дропы. Они **не являются восемью закрытыми задачами или двумя завершёнными направлениями**. Их текущий статус: код изменён, компиляция и нативный откат последнего состояния не подтверждены. Проверка форматирования diff не заменяет компиляцию.

Два самостоятельных направления с отсутствующей функциональностью:

1. **Runtime активатора:** в проходе 18.10 добавлены снимки/восстановление состояния боя, эффектов, атрибутов, питания и cooldown; снят общий запрет на несмертельный удар и добавлен ограниченный путь потребления наждачной бумаги. Это новые изменения исходников, ещё без подтверждения компиляцией и нативным прогоном. Смерть цели, потребление реальным игроком, произвольные внешние эффекты и creative IO вместе с world/entity эффектами остаются незакрытыми.

Другие обязательные остатки Create: непроверенные mounted/composed/sided обработчики, внешние эффекты модовых предметов, прямое удаление BE в обход штатных перехватов; нативная проверка нового creative/drop отката и предварительная защита optional mixin. Новые тестовые файлы, дополнительные поля журнала и безопасный отказ не засчитывать как закрытие этих направлений.

## Проход 18.10.2026: состояние боя и расходования предметов активатора

Изменения исходников:

- Новый `JointFormat=3` содержит состояние LivingEntity/FakePlayer: здоровье, поглощение, эффекты с родными данными, постоянные/временные атрибуты, питание, XP/инвентарь, используемый предмет, точные фазы cooldown, ссылки на участников и записи CombatTracker. Предыдущие форматы 1/2 остаются в обработчике; для старой руки новые поля исключаются из сравнения.
- Несмертельный удар по известной поддерживаемой цели больше не запрещается безусловно. Перехват урона добавляет также вторичные цели удара в ту же транзакцию. Смерть основной/вторичной цели и технического игрока оставляет неполную запись с запретом частичного отката.
- Разрешён известный путь потребления Create sandpaper/red sandpaper с предварительно загруженным предметом или полируемым предметом во второй руке. Поиск свободного предмета в мире не включён в этот контракт. Сценарий молока проверяет лишь прямой native `finishUsingItem` и восстановление эффектов: Create не выполняет такое потребление самим активатором через обычный DeployerHandler. Потребление настоящим игроком остаётся запрещённым для отката.
- Участники привязаны до применения, а технический игрок разрешается по контексту конкретного активатора. UUID владельца не используется для выбора настоящего игрока вместо FakePlayer. Неизвестный другой FakePlayer не подменяется владельцем. Действующее лицо журнала по-прежнему SYSTEM, владелец хранится отдельно.
- Обе стороны снимка проходят проверку схемы и доступных кодеков до изменения конечной точки. Проверяются типы списков, обязательные поля, конечные числовые значения, повторные атрибуты/модификаторы и cooldown. После загрузки native данных здоровье и поглощение выставляются повторно после восстановления временных атрибутов, чтобы промежуточный максимум здоровья не обрезал сохранённое значение.
- Между порционными шагами отката зарезервированные сущности не тикают. Детерминированные счётчики цели проецируются на текущий tickCount в отделённой копии; изменение другого состояния, перезагрузка или несовпадение остаётся конфликтом. Это не контракт полного восстановления произвольного AI, отложенных эффектов или чужих обработчиков событий.
- Runtime-интерфейсы для позднего встраивания в классы Minecraft/Create добавлены в правила сохранения имён ProGuard. Проверка обфусцированного JAR этой ревизии ещё не выполнена.
- Снимки снимаются в рамках активации. Проверка серверного тика содержит быстрый выход при отсутствии активного отката; оценка нагрузки и Spark этой ревизии ещё не выполнялись.

Проверки этой ревизии:

- Добавлены `CreateDeployerRuntimeTest` (схема, повреждённая история, проекция/переполнение счётчиков, cooldown, план старого и нового форматов) и native сценарии несмертельного удара/расхода наждачной бумаги, отмены/компенсации, конфликта питания/здоровья, эффектов/XP/cooldown и временного увеличения максимума здоровья. **Новые тесты не запускались.**
- Syntax-only разбор 24 изменённых/новых Java-файлов компилятором Java 17: 0 синтаксических ошибок. Это не разрешение типов, не компиляция под Java 21 и не проверка mixin на Minecraft.
- JSON optional mixin разобран; имена уникальны, все указанные исходники существуют. `git diff --check` пройден. Предпусковая проверка байткода новых mixin ещё не выполнена.
- `./gradlew test --offline` не дошёл до сборки: дистрибутив Gradle 8.14 отсутствует, wrapper пытается скачать его и получает `Network is unreachable`. JDK 21 и прежние Minecraft/NeoForge/Create бинарные зависимости в текущей среде отсутствуют. Установлен Java 17 с модулем компилятора; прежняя формулировка «компилятора нет» была неточной.
- Версия мода не повышалась; релизный JAR 2.2.0 не создан. Публичная отправка не выполнялась. Два крупных направления не объявляются завершёнными.

До продолжения функционального расширения требуется вернуть Java 21/бинарные зависимости и прогнать компиляцию, data/native проверки новой ревизии, прежние creative/drop сценарии и запуск без Create. ## Проход 17.10.2026: мировой creative IO и смешанные дропы

## Дополнительный подпункт — имя цели и конкретные изменения блоков

Ник игрока-цели снимается из GameProfile в момент события и сохраняется отдельно от автора, UUID и типа. Вывод использует сохранённое имя, включая историю после выхода/переименования. ## Подпункт Create — прямой получатель Container и обмен с mounted-депо

Штатная выдача DefaultMountedDispenseBehavior проходит через HopperBlockEntity.addItem и обходит capability insert/extract. Добавлен отдельный перехват этого вызова в существующей необязательной интеграции Create. Scope штатного выбрасывателя/раздатчика связывает изменения mounted-груза и фактически изменённые слоты получателя общим Transfer ID. Сохраняются вид/ID конструкции, сущность хранилища, механизм/локальная позиция, владелец, причина каждой части (включая пополнение), сторона, слот, предметы и компоненты до/после. Получатель описывается через явный DirectContainer-контракт. ## Подпункт Create — базовая вагонетка и обычная блочная воронка, оба направления

Этот коммит содержит восстановление и загрузку базовой вагонетки; прежний hash не объявляется доступным в данной копии.

Охвачены MinecartChest/MinecartHopper под конструкцией Create. Извлечение использует реальные tryTakeInItemFromSlot и capability-путь VanillaInventoryCodeHooks. Загрузка в обратную сторону охватывает весь нативный ejectItems: capability lambda$insertHook$2 и ванильный путь после getAttachedContainer. Для последнего захват начинается после выбора конкретного Container, но до removeItem у воронки, и завершается в finally после всей операции. Дополнительного выбора получателя и поиска соседних сущностей нет. Frame обычного вызова переиспользуется; вложенный вызов получает отдельный frame, ссылки на capture очищаются при завершении и исключениях.

Оба конца получают общий Transfer. Сохраняются BaseCart, слоты и предметы/компоненты до и после, вид/ID конструкции, UUID сущности конструкции, адрес/слот воронки, DirectContainer, сторона и машина. Итоговый снимок учитывает изменение ItemStack на месте и подавляет промежуточное изъятие/возврат при отказе. Пустая операция, заполненный инвентарь и отказ canPlaceItem не создают ложной передачи. Автоматика записывается как SYSTEM; существующий контекст конкретного автора учитывается. Блокировка базовой конструкции или адресной воронки останавливает изменение до обеих сторон. Ошибка после записи сохраняет наблюдаемый результат с Complete=false; общий планировщик запрещает такой откат.

Снимки ограничены выбранной базовой вагонеткой и конкретной блочной воронкой, максимум 512 слотов на Container; общий лимит — 512 изменений и 1024 адреса. Добавленного опроса всех вагонеток/инвентарей на тиках нет. BaseCartInventoryAuditMixin и новые ванильные mixin используют CartAutomationHooks без вызова классов Create при отсутствии observer. Это исправляет прежний сбой setItem обычной вагонетки без Create; аудит всех optional mixin не объявляется завершённым.

## Завершение Create: межконструкционный обмен, общий откат передачи и история связей

Рабочая точка до этапа — 19ac57a. Изменения ниже уточняют прежний список пробелов: межконструкционный обмен теперь поддержан новым протоколом, а полный структурный откат остаётся незавершённым. Версия остаётся 2.1.11; выпускной JAR, обфускация и публичная отправка не выполняются.

Автоматический обмен больше не теряет вторую конструкцию. Оба участника получают запись общего Transfer в собственной истории; каждый manifest содержит отделённые Cargo-снимки всех участников, внешних слотов/баков и всосанных предметов/посылок. Сохраняются вид и логический ID конструкции, UUID сущности хранилища, измерение, локальный слот/бак, механизм, компоненты и отдельный постоянный UUID вагона. Два вагона одного поезда разделяют историю Train ID, сохраняя разные адреса хранилищ. Неполная операция, потерянный участник, нарушенный баланс, подмена компонентов/UUID и присвоение одного хранилища разным конструкциям не принимаются планировщиком.

Добавлены `/log cart undo-transfer <ID> <запись>` и `confirm-transfer`: это отмена одной законченной автоматической передачи для cart/train/bearing/other. История и поиск по ID теперь охватывают все четыре вида через обязательный constructionId-фильтр, включая SQL feed/split/fallback. Старый одиночный cart rollback отклоняет передачи, требующие участия второй конструкции.

Новый coordinator восстанавливает mounted-предметы/обычные баки Create, проверенные внешние блочные обработчики/DirectContainer и всосанные ItemEntity/PackageEntity. Предварительно сверяются все адреса и содержимое, затем каждый endpoint повторно проверяется перед записью. Применение, финальная сверка и обратная компенсация выполняются по шагам с бюджетом тика. Отмена и ошибка возвращают уже изменённые endpoints; ошибка компенсации оставляет резервации и явную диагностику. История повторно проверяется на worker после резервирования: более позднее изменение, сцепка, переход жизненного цикла или предыдущий откат запрещают отмену старой передачи, даже если груз снова совпал. Служебная запись отката сохраняется в истории каждого участника. Отменённый или заменённый запрос предпросмотра не может позднее активировать старый результат.

Резервируются обработчики, меню, сущности и логические корни конструкций. Блокировки охватывают груз, setBlock, взаимодействие и разборку; для поездов — tick/earlyTick всего Train и остальных вагонов того же корня. Физика сцепки и tick MinecartController не обходят резервирование базовой вагонетки. Действия сцепления, разрыва и разворота цепочки проверяют зарезервированных участников до изменения, включая работу при отозванной авторизации. Это защита текущей транзакции, а не реализация совместного восстановления самой сцепки.

Жизненный цикл train/bearing/other получает типизированную историю сборки/загрузки, удаления/выгрузки и разборки. Сохраняется полный отделённый Entity NBT существующего представления и форма после перехода; перед разборкой сохраняются payload и связи. Отдельно записываются vehicle/passengers/stabilized-связи, локальные адреса вложенных конструкций и, когда Carriage уже привязана, её UUID/измерения представлений/признак портала. Ошибка разборки получает Complete=false. Это не снимок всех фактически размещённых мировых блоков и не восстановление графа железной дороги. Типизированные события заменяют дублирующие generic spawn/leave и лишнее legacy-кеширование; неизвестные типы аддонов сохраняют прежний путь.

Сцепление/разрыв сохраняет общий Operation ID, Complete и native MainCoupling/ConnectedCoupling до/после на каждом фактически изменённом контроллере. Scope штатного сцепления охватывает обе стороны и разворот существующей цепи; событие доступно в истории участвующих конструкций. Статус stall не выдаётся за изменение сцепки; no-op не создаёт строк. Известный инициатор сцепления сохраняется через CauseContext. Произвольная пара прямых вызовов coupleWith вне общего нативного scope остаётся отдельными событиями.

## Подпункт: восстановление одной разборки контроллера

Разборка mechanical/windmill/clockwork bearing, mechanical piston, rope/elevator pulley теперь захватывается на уровне контроллера до его первой мутации. Scope сохраняет полный Entity/payload каждого участника, связи и логические ID, начальные блоки мира и конечные BE/инвентари после unmount, созданные ItemEntity/SuperGlue и общий Operation UUID. Добавлены runtime-флаги AssembleNextTick/NeedsContraption, отсутствующие в обычном NBT. Entity-level lifecycle и промежуточные generic block/cargo записи не дублируют захваченную операцию. Контекст механизма сохраняется отдельно и не заменяет UUID операции строкой.

Общий StagedContraptionRestore собирает detached payload по блокам, акторам, хранилищам и остальным native спискам; существующий StagedCartRestore использует его через адаптер. Неизвестное состояние палитры отклоняется при точной сверке codec round trip. Новый структурный Job предварительно сверяет весь мир/контроллеры/дроп, отсутствие Entity UUID и более поздних событий всех участников; повторяет историю после резервирования. Затем восстанавливает блоки, удаляет зарегистрированные эффекты, добавляет сущности с исходными UUID и привязывает их к контроллерам. Финально сверяются payload, связи, runtime и реальные controller references, включая обе стрелки clockwork. Применение и обратная компенсация выполняются по шагам с бюджетом 1 ms / максимум 16 шагов за тик. Отмена или ошибка после мутации возвращает уже затронутые endpoints; при ошибке компенсации в рабочем тике резервации сохраняются.

Native загрузка кинетического BE выполняется с явным снятием wasMoved: иначе Create пропускает Running/Angle/kinetic NBT после установки блока. Блоки применяются с UPDATE_MOVE_BY_PISTON, чтобы удаление магнита/каната при откате не запускало обработчик обрыва и не сбрасывало pulley offset. Эти изменения проверены и на прежнем полном cart rollback. Контроллеры блокируют assemble/disassemble до мутации, даже если авторизация отозвана. Preflight теперь требует, чтобы shadow-поле было объявлено непосредственно в target: наличие поля только в superclass не означает, что Mixin сможет его применить.

Добавлены `/log cart undo-disassembly <ID> <запись>` и `confirm-structure`; общий `cancel` охватывает новый Job. История предлагает команду для structural_disassemble, текстовые подробности показывают изменения State/BE/инвентарей/runtime. Один снимок допускает до 64 сущностей, 8192 адресов мира, 512 эффектов; суммарный размер копий для историй всех участников ограничен 128 MiB. Ошибка конечного снимка/превышение лимита оставляет небольшой явный Complete=false маркер с причиной и запрещает восстановление.

## Продолжение Create: атрибуция, реестры и сцепки (11.10.2026)

В основную ветку перенесены исправления достоверности из 2.1.12/2.1.13 без изменения версии разработки 2.1.11. Очередь сохраняет отдельные события, точные координаты и полное содержимое снимков. Владелец конструкции, FakePlayer, ближайший игрок и последний посетитель больше не заменяют исполнителя. Автоматические действия Create записываются как SYSTEM; прямое действие настоящего игрока сохраняет его UUID. Владелец остаётся отдельным полем механизма. Это распространяется на груз, активатор, меню/депо, подбор добычи и сборку поезда. В сохраняемой причине предметов/снарядов разделены Owner и Actor; старый Owner не становится новым Actor. Нативный entity tick маскирует постороннюю внешнюю причину и восстанавливает только явно сохранённого исполнителя. Снимок получателя подбора отделён от actorUuid: технический получатель может быть SYSTEM, а откат сверяет его действительный инвентарь по UUID в связанных снимках. Старые записи БД не исправляются задним числом.

Расширен структурный откат одного захваченного вызова disassemble:

- Граф зеркальных шкивов захватывается до мутации полностью: родитель, ведомые контроллеры, двусторонние связи и точный offset. План отклоняет пропущенную сторону, иной тип, повторное ребро и цикл.
- Подтверждено восстановление настоящей стабилизированной дочерней конструкции: исходные UUID, payload, вложенность, сундук с компонентами, SuperGlue и компенсация после создания всех участников.
- Для лифта добавлен endpoint ElevatorColumn: существование в реестре, координаты, контакты, Active, TargetY/TargetAvailable, версия названий. Контакты входят в мировую транзакцию. Сохраняются также отсутствующие в обычном NBT поля контроллера (скорость предыдущего шага, прибытие и клиентская цель). Колонка резервируется; нативные изменения цели/состава/активности блокируются до завершения или компенсации. Отсутствующая после разборки пустая колонка также восстанавливается.
- Ветряк сохраняет связанную кинетическую сеть и все её загруженные блоки: состав и веса участников/источников, полные параметры реестра, unloaded-параметры и runtime-флаги блоков. Откат возвращает скорость соседнего вала; компенсация возвращает остановленную нагрузку. Прямая мутация сети и её повторное создание блокируются резервированием. Новая сеть, отсутствовавшая в захваченном наборе, делает операцию неполной и не принимается для отката.

Добавлен самостоятельный откат сцепок `/log cart undo-coupling <ID> <запись>` → `/log cart confirm-coupling`. Новый снимок coupling Format=2 содержит весь затронутый граф вагонеток, полное NBT контроллеров, идентичности конструкций и CouplingId. Захват проходит по действительным существующим связям только во время операции, без обхода мира по тикам. План проверяет обратные стороны, измерения, длину и отсутствие циклов. Транзакция возвращает контроллеры и native leading registry, сверяет последующую историю всех конструкций, удерживает чанки и блокирует изменения цепочки. Отмена после первой/последней записи и ошибка после записи компенсируются. Формат 1 остаётся доступным для просмотра, но не принимается как полный снимок отката. Расцепление through-contraption с разборкой тела получает неполный снимок: этот побочный эффект требует совместной структурной транзакции, а история исходного участника сохраняется.

## Проход 12.10.2026 — нативная разборка обычного поезда

Структурная транзакция расширена на успешный `Train.disassemble`: один состав с загруженными вагонами в одном измерении. Используются существующие команды `/log cart undo-structure <ID> <запись>` → `/log cart confirm-structure`; ID конструкции соответствует настоящему `Train.id`. Сохраняется полный native Train/Carriage NBT, логические UUID вагонов и UUID сущностей, геометрия и положение представлений, общий item/fluid cargo, расписание, навигация и отсутствующие в native NBT рабочие поля. Прямое действие у станции берёт причину настоящего отправителя; автоматическая разборка остаётся SYSTEM. Владелец состава не становится исполнителем.

Откат готовит NBT на существующем worker и поэтапно создаёт отсоединённый Train/Carriage и тела вагонов. Общий груз подключается к настоящему `TrainCargoManager`, без изменения статического fallback storage. Возвращаются реестр RailwayManager, очередь движения/ожидания, ближайший поезд станции и собственные записи занятости/резервирования сигналов. Временные ссылки SignalEdgeGroup, которые Create очищает лишь следующим railway tick после удаления состава, записываются в фактическом состоянии; компенсация сохраняет ссылки, существовавшие перед началом отката. Посторонние составы и путевая топология не восстанавливаются из чужого снимка.

Полный снимок графа используется как свидетельство конфликта. Замена графа, изменение его NBT, чужой поезд/резерв в затронутой сигнальной группе, занятой ID, изменённый блок/груз или пересечение с другой конструкцией запрещают применение. Эпоха нативных изменений графа проверяется между шагами; позднее изменение приводит к компенсации. Подготовленный native payload, дополнительные runtime-поля и навигация сверяются до первой записи мира и перед commit. Отмена после блоков, появления вагонов и регистрации RailwayManager возвращает послеоперационное состояние мира и убирает восстановленный состав.

На время применения мировой части останавливается `GlobalRailwayManager.tick` (симуляция всех поездов); worker-подготовка и чтение истории не требуют этой остановки. Зарезервированный состав, расписание, управление, станция и её depot-инвентарь защищены от нативных изменений. Известный DepotItemHandler допускается только с установленными блокировками; неизвестные handlers по-прежнему отклоняются. Если полный BE NBT уже восстановил точные слоты, повторная запись через немодифицируемый capability не выполняется. Строгая сверка слотов остаётся обязательной.

Исправлены два обнаруженных нативных эффекта сериализации: чтение снимка больше не сбрасывает одноразовый `OrientedContraptionEntity.forceAngle`/ForceYaw; загрузка прежнего NBT станции при откате очищает отсутствующий `PrevTrainName`, вместо сохранения имени разобранного состава. Дополнительная ориентация вагонов восстанавливается и проверяется отдельно.

Проверено на Create 6.0.11 / NeoForge 21.1.219 / Java 21:

- `CREATE_TRAIN_ROLLBACK_NATIVE_OK`: 22 сценария настоящей сборки bogey/chest/tank carriage и нативной разборки Train. Один/два вагона, одна/две тележки вагона, обратное направление, moving/waiting queue, расписание и его runtime, сигнальный резерв, item/fluid components, успешный откат, три этапа отмены, ошибка после записи, ранние/поздние конфликты графа, станции, сигналов, UUID, груза и пересечения тел; отдельный отказ портальной разборки.
- Семь повреждённых/неполных вариантов реестра отвергнуты; отдельно проверено, что повторный снимок не потребляет ForceYaw, а блокировки не дают изменить поезд, расписание, станцию и depot.
- Общая регрессия завершилась `AVILIX_CREATE_SMOKE_OK`, включая structural (38), coupling (25), linked transfer, world transfer, cargo, menu, механизмов и остальные прежние проверки.
- `CREATE_PREFLIGHT_OK`, `CREATE_PREFLIGHT_FAILURE_NATIVE_OK`, `CREATE_ABSENT_NATIVE_OK` и нативный vanilla hopper/cart без Create прошли. Async/HTTP storage regression завершилась `TEST_MAIN_OK` (74 сохранённые записи); прежние проверки акторов/координат и полного сохранения структурных payload также прошли.

**Остаток Create:** произвольное восстановление поездов после unload/портального перехода и портальных представлений; совместный откат coupled through-contraption disassembly и внешнего удаления контроллера; рука активатора вместе с изменёнными целями; генерация/уничтожение creative-источниками; смешанная цепочка drop → suction → pickup/merge; неизвестные mounted/composed/sided контракты. Текущая разборка не поддерживает неполностью загруженный/портальный состав и пассажиров/активного водителя: снимок помечается неполным или план отклоняется. Нативные клиентские анимации не являются сохраняемой контрольной точкой. Граф ограничен 8192 узлами, состав — 64 вагонами, структурный payload — 128 MiB; превышение не превращается в обрезанный успешный откат.

Бюджет coordinator остаётся мягким (1 мс/до 16 шагов за тик): отдельный native codec или полная сверка графа могут превысить его. Spark, настоящий модпак, GUI клиента, AuthCore/production emit, реальный ClickHouse и финальный выпускной/обфускационный прогон ещё не проверены. **Вся ветка Create не объявляется завершённой; версия разработки остаётся 2.1.11, release 2.2.0/JAR не выпускается в этом проходе.**


## Проход 12.10.2026 — совместная сцепка и внешнее удаление контроллера

Сохранено незавершённое состояние перед срочными патчами; исправления 2.1.14–2.1.16 перенесены в разработку. Версия разработки 2.1.11 и запрет на выпуск 2.2.0 до общего финального этапа сохранены.

### Разборка через сцепленную конструкцию

Транзакция захватывает весь затронутый граф: тела разобранных конструкций, блоки и грузы в мире, состояния базовых вагонеток, native контроллеры сцепки, needsEntryRefresh и очереди CapabilityMinecartController. Сохраняющиеся соседние конструкции остаются неизменёнными участниками с отдельной проверкой дальнейшей истории. Проверяются связь тела с базой, каждый край сцепки, порядок пассажиров, исходные UUID/логические ID, runtime и очередь. Применение резервирует реестр; компенсация возвращает мировые блоки, созданные тела и частично записанные контроллеры. Операция не выдаёт отдельную неполную строку простого расцепления.

`CREATE_COUPLED_STRUCTURAL_NATIVE_OK`: 19 нативных сценариев. Коммит/отмена после мира, появления тел, первого и последнего контроллера; цепочка с двумя through-contraption рёбрами; конструкция на двух вагонетках; сосед без тела; settled/pending registry; компоненты предметов/жидкостей; конфликты мира/груза/реестра/выжившего соседа/эффектов/UUID; ошибка после записи; locks. Шесть повреждённых вариантов полного снимка отвергаются.

### Разрушение/замена контроллера

Создание снимка перенесено наружу `disassemble`, до первой смены блока; для `destroyBlock` — до выпадения предмета самого контроллера. Полная операция включает этот дроп, тело, груз, соседние контроллеры, кинетический реестр и ElevatorColumn. Core bridge не требует Create для загрузки. Изменение обычного блока не создаёт структурного scope. Незавершённая/неизвестная операция и замена на другой controller runtime не превращаются в допустимый неполный откат.

Флаг `ControllerRemoved` различает захваченное исчезновение контроллера и конфликт его более поздней замены. План разрешает отсутствие controller BE только при согласованном снимке этой операции; до применения проверяются точные after state/NBT/slots/реестры. Восстанавливается новый BE с исходным runtime и привязкой исходных UUID тел. Откат забирает соответствующие дропы, компенсация возвращает их. `destroyBlock` на зарезервированном адресе блокируется до выпадения предметов.

При отмене после восстановления ветряка найдена дополнительная native мутация: удаление восстановленного контроллера меняет NetworkDirty соседнего вала, уже компенсированного ранее. Добавлены отдельные бюджетируемые фазы runtime/registry settlement после всех мировых записей и после компенсации; сохранённые данные не нормализуются для сокрытия расхождения. Повторная отмена не сбрасывает прогресс компенсации, в том числе после отзыва авторизации. Защита railway epoch действует и в новой фазе.

`CREATE_CONTROLLER_REMOVAL_NATIVE_OK`: 25 сценариев. Настоящий destroyBlock с дропом контроллера; подшипник, часовой подшипник с двумя телами, поршень, шкив, зеркальные шкивы, ветряк с нагрузкой, вложенная конструкция, лифт с контактами и пустой колонкой; успешный откат и отмена после появления всех тел. Отдельно setBlock в воздух/камень/сундук, отмена после первой записи, конфликт, ошибка после записи, locks и повреждённый флаг удаления.

## Подпункт 13.10.2026: совместный откат руки и прямых целей активатора

- Совместный отделённый снимок `CREATE_DEPLOYER_ACTION`: полный 41-слотовый инвентарь/selected, компоненты предметов, параметры механизма, состояние BreakingProgress/PlacedTracks/Effects/Timer; изменённые прямые блоки/BE/слоты, поддержанные сущности и редкие изменения mounted-груза. Снимки снимаются при фактических операциях, не на пустых тиках; сериализация больших payload в очередь остаётся отложенной.
- Нативные `tryGrabbingItem` и `tryDisposeOfExcess` становятся отдельными совместными операциями руки/груза. Это позволяет откатывать цепочку последовательно с конца; последующий обмен не игнорируется в проверке истории. Поддерживается расход груза schematic printer внутри активации, когда он проходит известные mounted contracts; творческое supply/void остаётся следующим самостоятельным подпунктом.
- `/log cart undo-transfer <ID конструкции> <ID записи>` и `confirm-transfer` принимают complete совместные действия. Проверяются актуальная история и оба состояния всех целей; live-участники резервируются до второй проверки истории. Применение/проверка/компенсация используют прежний лимит 1 мс / 16 шагов в тик. Поддерживается отмена до записи, после первой и после последней записи; повторная отмена не обнуляет ход компенсации.
- Рука восстанавливается в существующем техническом игроке, а настройки/личность механизма должны совпасть. Производственный модпак, портал с переносом поезда, сериализуемое боевое состояние и полный откат потребления остаются открытыми пунктами версии 2.2.0; выпуск не объявлен.

### Атрибуция лавакаста (14.10.2026)

- При `LiquidBlock.onPlace/neighborChanged` NeoForge 1.21.1 вызывает `FluidInteractionRegistry.canInteract` вместо старого ванильного пути. Именно внутри него булыжник мог наследовать чужой `CauseContext` от текущего действия игрока. Обособлен этот вызов и оба ванильных пути образования булыжника/камня: реакция получает системный источник, `actorUuid=null`; непосредственное размещение воды игроком сохраняет его UUID. Анонимный физический результат не присваивается игроку только по соседству или по последнему использованию ведра: при двух источниках жидкости это не доказательство авторства.
- `FLUID_ATTRIBUTION_NATIVE_OK` проверяет настоящие преобразования воды/лавы в булыжник и камень при активном контексте другого игрока; тестовый mixin наблюдает вход в `Level.setBlock`. Продукционная авторизация AuthCore на этом стенде отсутствует, поэтому чтение уже записанных в ClickHouse строк этим тестом не проверяется. Дальнейшая точная привязка лавакаста к его инициатору потребует устойчивого учёта происхождения обоих потоков и разрешения конфликтов между игроками.

### Продолжение составных capability: жидкостная чаша

- Для точного `CombinedTankWrapper` у нативного `BasinBlockEntity` подтверждён порядок output(2) → input(2), в отличие от предметных слотов. Mixin захватывает изменившийся внутренний бак через внешний capability во время реального fill/drain, а rollback пишет в конкретный `SmartFluidTank` с его callback, сохраняя исходный порядок и ёмкость. Источник, размер и обе дочерние capability повторно проверяются при откате; переставленные баковые обработчики отклоняются. Вложенные вызовы дочерних баков не дублируют запись.
- `CREATE_BASIN_FLUID_COMPOSITE_NATIVE_OK: 8 scenarios` и полный `AVILIX_CREATE_SMOKE_OK` прошли: native fill/drain, частичный объём, компенсация, конфликт, замена/выгрузка и блокировка. Отрицательный сценарий с переставленными output/input handler также пройден. Произвольные составные жидкостные обработчики остаются вне этого точного контракта.

### Подготовка захвата мировых creative-хранилищ (15.10.2026)

- Подготовлены обёртки фактического результата item insert/extract и fluid fill/drain для мировых creative crate/tank. В открытом server-thread scope они сохраняют направление, шаблон, полученный или поглощённый ресурс и известный адрес; ошибочный результат и исключение делают операцию неполной. Общий automation-манифест переносит эти сведения в обе стороны и помечает совместный откат неполным. Быстрый путь mounted-груза больше не пропускает манифест при наличии world creative IO.
- Новые mixin **не включены в загрузочную конфигурацию**: в текущем рабочем окружении отсутствуют JDK 21 и классы закреплённого Create 6.0.11/NeoForge. До проверки сигнатур preflight, native IO, вложенности и поведения без Create включать их нельзя. Подготовленный код сейчас не меняет runtime и не означает поддержку мировых creative-хранилищ.
- Уже действующие перехваты выдачи capability и стандартных item/fluid handler теперь помечают открытый automation-scope неполным при известном мировом creative-блоке или точном типе его handler. Это защитный отказ для достигнутых путей, включая заранее закешированный handler, если он проходит стандартный перехват. Путь, который обходит оба перехвата, остаётся возможным; только включение и нативная проверка специальных mixin закроет этот пробел. Поиск блока выполняется лишь при работе с capability в активной операции, не на пустом тике.
- Следующий шаг: восстановить native classpath, проверить класс и точные overloads, включить mixin и прогнать реальные обмены с конечным получателем, отсутствие/смену адреса и шаблона, конфликт, lock, отмену и компенсацию. Затем добавить отдельный полный rollback-контракт мирового источника; до этого манипуляция им не считается обратимой. Операция только с world creative IO без установленной конструкции пока не даёт строки в журнале и тоже остаётся незакрытой.

### Параллельные границы смешанного дропа и боя активатора

- Слияние предметной сущности, помеченной ID конструкции, теперь создаёт отдельную неполную `actor_result` запись для каждой затронутой конструкции. Запись появляется только при фактическом изменении пары сущностей либо при исключении. Откат периода вагонеточной конструкции уже отклоняет такой результат; состояние двух UUID, их слияние с посторонним дропом и последующий подбор не выдаются за сбалансированную цепочку. Проверка обычных предметов использует имеющийся nullable origin tag и не выделяет пустой persistent NBT на каждом merge. Полный обратимый контракт слияния ещё не реализован.
- Если всасывание воронки уже захватило один из дропов внутри текущей automation-операции, его последующее слияние с другим дропом помечает общий манифест неполным. Снимки двух стеков делаются только для затронутых сущностей и только на самом вызове слияния; пустые тики не сканируются.
- Каждый вызов атаки живой цели активатором помечает совместный снимок неполным независимо от дельты здоровья: блокированный удар тоже может изменить combat tracker и эффекты. Создание строки действия при нулевом результате остаётся прежним. Полный возврат боевого состояния и смерти цели по-прежнему открыт.
- Неполный результат активатора сохраняется как барьер отката даже при выключенной пользовательской категории атак/взаимодействий. Иначе `CartRollbackPlan` вообще не увидит неподдержанное действие в периоде. Для полного случая по-прежнему действует обычный фильтр категории.
- Эти два изменения проверены только статически (`git diff --check` и структура связки), без native smoke в текущем окружении. Перед включением в выпуск требуется Java 21 compile и сценарии Create 6.0.11 на сервере: слияние tagged+tagged разных конструкций и tagged+обычный дроп, отсутствие изменения, исключение, удар в щит/нулевой урон, успешная атака и отклонение плана до записи мира.

### Текущая сверка Create (17.10.2026)

- В рабочей конфигурации `avilixlogger_create_trains.mixins.json` **уже перечислены** `WorldCreativeCrateAuditMixin` и `WorldCreativeTankAuditMixin`. Ранняя запись выше об их невключённости устарела. Preflight сверяет сигнатуры при запуске и отключает Create целиком при несовпадении, но это не заменяет native испытаний самих операций.
- Захват и откат мирового creative endpoint теперь обращаются к capability с одной и той же сохранённой стороной, а не запрашивают без стороны при повторной проверке. По архиву исходников Create 6.0.11 подтверждены соответствующие overrides `BottomlessItemHandler` и `CreativeSmartFluidTank`; работа перехватов на сервере этим не подтверждена.
- Автоматические операции mounted/world конструкций и события загрузки/удаления предметной сущности конструкции не наследуют случайный ambient `CauseContext` игрока: строки пишутся как `SYSTEM` с сохранением ID конструкции. При сборке вагонетки ambient игрок признаётся инициатором только для `USE_BLOCK` по точной позиции сборщика; долговременная запись владельца остаётся отдельной.
- `git diff --check` проходит. В этом окружении доступна только Java 17, прежний native classpath в другом scratch-каталоге отсутствует; `./gradlew compileJava --offline` не запускает сборку, поскольку wrapper пытается скачать Gradle 8.14 и сеть недоступна. Поэтому **Create пока не закрыт**: нужен Java 21 compile, серверный прогон мирового creative IO и смешанных дропов/боя, а затем решение по оставшимся неподдерживаемым контрактам и состоянию поездов/активатора. Не выдавать финальный JAR 2.2.0 на основании этих статических проверок.

### Откат периода вагонетки с мировым creative endpoint (17.10.2026)

- План одиночной вагонетки теперь сохраняет подтверждённые мировые creative crate/tank IO вместе с конечными слотами, грузом и предметами мира. Раньше вся такая история отклонялась, хотя одна передача уже имела проверку источника. Перед любыми изменениями Job резервирует исходный блок/handler через существующий `CreateWorldCreativeRestore`, а после отката конечных участников и перед commit повторно сверяет блок, BE, capability, сторону, шаблон и размеры. При отмене конечные участники компенсируются прежним порядком; неизменный creative endpoint не требует записи назад.
- Если тот же creative-блок в периоде изменён как блок либо как конечный слот/бак, план отклоняется до запуска. Другие конструкции в одной передаче и неполные/несбалансированные снимки по-прежнему отклоняются общим валидатором. Добавлены сценарии построения плана для предмета/жидкости, выдачи/поглощения и конфликта с изменением блока.
- Это **подготовленный код, не пройденный native smoke**: Gradle/Java 21/Create 6.0.11 и реального сервера в текущем окружении всё ещё нет. Смешанный drop → merge → suction → pickup и его совместный откат остаются незавершёнными; ранее добавленные `actor_result` барьеры продолжают запрещать частичный откат через слияние. Доступность отката периода с мировым creative источником нельзя обещать до серверного прогона конфликтов, отмены и компенсации.
- Для подбора уже объединённой предметной сущности теперь записываются изменившиеся слоты реального получателя до/после, его UUID, прежний/оставшийся стек дропа и исходы вызова. Снимок ограничен 41 слотом именно в событии подбора, а при большей ёмкости помечается усечённым. Эта запись остаётся `Complete=false`: сама по себе она не восстанавливает оба исходных UUID и не снимает барьер совместного отката слияния. Нативный прогон подбора, включая отмену сторонним модом и частичное принятие, ещё необходим.

### Активатор Create: сверка runtime и старых записей (20.10.2026)

- Активный предмет живой цели и технического игрока теперь сохраняется тем же кодеком, что и расширенный инвентарь: компоненты сериализуются с допустимым количеством, а фактическое количество, в том числе 1024, записывается и читается отдельно. Ошибка снимка прерывает полный захват. В native smoke добавлен сценарий возврата предмета в использовании с количеством 1024; в detached проверке отклоняется нулевое количество.
- Ранние форматы совместной операции (1/2) не содержали снимка здоровья, эффектов, атрибутов и боевых ссылок цели. План теперь отвергает откат таких записей с живой целью до начала записи мира. Исторический откат одной руки и неживых целей остаётся допустимым. Формат 3 проверяет runtime каждой существующей живой цели.
- Реальное кормление игрока уже записывается с явным типом и барьером `Complete=false` до применения `finishUsingItem`: его инвентарь, статистика и достижения требуют отдельного полного контракта. Расширение на `ServerPlayer` нельзя считать готовым по снимку технического игрока. Native fixture с новым сценарием здесь не запускался: отсутствуют Java 21, Gradle 8.14 и зависимости Create/NeoForge. Выпускной JAR 2.2.0 и завершение направления активатора этой статической сверкой не подтверждаются.

### Два крупных направления, продолжение 17.10.2026

- **Мировые creative endpoint:** если нативный handler реально отдал/поглотил ресурс, но адрес, capability, размер снимка или результат не удалось проверить, открытый scope теперь сохраняет ограниченную запись `UnverifiedCreativeIO` с причиной и доступным payload. При отсутствии конструкции появляется отдельная системная строка по адресу самого механизма; при наличии конструкции полный манифест остаётся `Complete=false`, а операция без cargo оставляет отдельный `actor_result` барьер. Ранее такие случаи могли закончиться без строки вообще. Сканирования пустых тиков и попытки отката неизвестного адреса нет.
- **Смешанные дропы:** успешное слияние получает собственный UUID операции, и до 32 UUID образуют наследуемую цепочку в уцелевшем предмете. Строки слияния содержат UUID, признак точного сохранения количества/компонентов и обоих исходных сущностей; подбор включает цепочку. При переполнении история явно помечается. `Complete=false` оставлен намеренно: связанный обратимый план для всех UUID и конечного инвентаря пока не написан.
- Эти изменения **не закрывают два направления целиком**. Для creative нужны Java 21 compile, native прогон и AuthCore/ClickHouse; для цепочки дропа требуется согласованный multi-entity rollback, включая чужую конструкцию/обычный дроп и последующий pickup. Пока инструментарий среды (JDK 21, Gradle 8.14, native classpath) недоступен, объявлять такой контракт проверенным нельзя.
