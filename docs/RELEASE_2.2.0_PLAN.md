# Подготовка AvilixLogger 2.2.0

Исходная версия: 2.1.11, исходная точка: `0be97f5`. Рабочая ветка: `fix/release-2.2.0`. Версию и выпускной JAR не менять/не собирать до отдельного финального этапа. После каждого законченного этапа отправлять изменения в Git, дать понятный отчёт и ждать ответа пользователя.

## Обязательный порядок

1. Оставшиеся участки Create/контрапций, небольшими самостоятельными этапами. Этап 1: связанная автоматизация с ванильными двойными сундуками. Далее: sided/составные обработчики, прямой обмен Container/воронок и другие пути автоматизации, дальнейшее движение/использование груза; сцепки и вложенные конструкции, согласованные откаты. Конкретные границы следующего этапа выбирать по проверяемому участку. Не считать текущие отказы безопасного одиночного отката полной реализацией.
2. Подробные смерти: сообщение, тип/идентификатор DamageSource, прямой источник и ответственный убийца (в том числе снаряды/модовые сущности), место и контекст; вывод в GUI.
3. Изменения текста установленных табличек: обе стороны, старый/новый текст, автор/источник и позиция; определить серверный мод редактирования из списка и проверить его путь.
4. Завершить Backpacked поверх существующей частичной интеграции: постоянный и короткий ID, история владельцев/передач, содержимое, улучшения/настройки, автоподбор, полный жизненный цикл и причины уничтожения, поиск/история в GUI. Проверять для NeoForge 1.21.1, а не переносить API из ветки 26.1.
5. Аудит каждого оставшегося серверного мода из приложенного пользователем списка: искать первичные источники для NeoForge 1.21.1, фиксировать точную версию, интерфейсы/контейнеры/механики и каждый подтверждённый/незакрытый путь. Исключить моды Avilix и исключительно клиентские моды; стороны остальных подтвердить по метаданным/исходникам. Запуск без краша не равен полноте логирования. Разбивать аудит по группам модов.
6. Только после завершения и проверки всего: интеграционный прогон, измерения Spark/нагрузки, проверка обфускации и привязки к серверу, сборка 2.2.0 и краткий перечень изменений.

## Требования, действующие на всех этапах

- Минимальная нагрузка на TPS сервера и FPS клиента. Живые world/inventory данные читать только в серверном потоке; отделённые снимки, сериализацию, БД, поиск и построение планов обрабатывать в фоне. Бюджетировать применение/компенсацию мира по тикам.
- Команды и GUI должны оставаться понятными. Нельзя объявлять отрисованный GUI или авторизованный журнал проверенными по одному dev-only fixture.
- Необязательные моды не являются жёсткими зависимостями. При отсутствии/несовместимости интеграция отключена, её команды и элементы GUI скрыты.
- До 2.2.0 обязательно реализовать и проверить защиту загрузки от неверных/несовместимых optional mixin: предварительные проверки целей/сигнатур/полей, согласованное отключение всей затронутой интеграции, диагностика, инъекция ошибок/отсутствующих целей. Одного `required=false` и `defaultRequire=0` недостаточно для обещания отказоустойчивости. Базовые vanilla mixin также требуют проверки конфликтов.
- В этой ветке CI выполняет compile/test и dev server fixture без задач `build`, `jar`, `obfuscateJar` и загрузки JAR.

## Этап 1

Реализовано: связанные передачи с двойными обычными сундуками/ловушками, единый адрес общего слота, данные обеих половин в истории/GUI, проверки обеих половин до отката, резервирование обеих половин и компенсация слотов. Новых обязательных зависимостей и mixin не добавлено.

Проверки завершены локально без упаковки JAR:

- `git diff --check` и проверка небезопасных instance-инициализаторов mixin пройдены.
- Изменённые Java-классы скомпилированы `javac` Java 21 против NeoForge 21.1.219 / Minecraft 1.21.1, Create 6.0.11 и предыдущих классов проекта. Стандартный Gradle запуск не разрешил зависимости из-за отсутствия сетевого доступа из JVM; для проверок восстановлен отдельный classpath из прежнего dev-стенда и официальных артефактов. Полная Gradle/ProGuard сборка не выполнялась.
- `AsyncPipelineTest`: история/пагинация, слоты 0/26/27/53 двойного сундука, непрерывность снимков обеих половин, компоненты, неполные операции, очередь, повторная доставка, журнал и HTTP fixture сохранения снимков пройдены.
- Изолированный сервер NeoForge 21.1.219 с Create 6.0.11 и AE2 19.2.12 запущен напрямую из классов. Получены `CREATE_AUTOMATION_NATIVE_SMOKE_OK: 41 scenarios` и `AVILIX_CREATE_SMOKE_OK`: новые проверки двойных сундуков и прежние проверки идентичности/восстановления структуры, предметов/жидкостей, commit/cancel, меню, получателей и дропа пройдены. Исправлен выявленный тестом отдельный штатный класс сундука-ловушки.
- Это dev-only fixture без AuthCore, не обход авторизации рабочего журнала. Полный модпак, авторизованный ClickHouse, отрисованный GUI и нагрузка Spark не проверены.

Изменения сохранены локальным коммитом в `fix/release-2.2.0`. Отправка в публичный `Vlad-Ras/Logger` отклонена автоматической проверкой: требуется явное разрешение пользователя на этот публичный адрес. Исходный список модов исключён из коммита; его публикация не входит в повторную отправку. До разрешения не обходить блокировку другим способом.
