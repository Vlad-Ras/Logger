# AvilixLogger 2.1.10 — нагрузка и сохранность записей

Продолжает изменения 2.1.9: StackWalker отсутствует; снимки мира отделяются от живых объектов, сравнение/кодирование/обогащение/дедупликация выполняются в фоне. Типы событий, AE2, GUI, команды, авторизация AvilixAuthCore и обфускация сохраняются.

## Серверный поток

- Состояния блоков передаются как неизменяемые BlockState; SNBT создаётся в фоне и кэшируется с лимитом 8192 состояний.
- Снимки контейнеров используют прямой API NeoForge, повторно используют уже прочитанные BlockState/BlockEntity и не копируют весь инвентарь второй раз. Обычные предметы без component patch сохраняются кратко; любые изменённые компоненты сохраняются полностью.
- Частые вызовы AvilixAuthCore используют MethodHandle без отражения и создания массива аргументов. Проверка выполняется при каждом вызове, её результат не кэшируется.
- Контекст тиков использует ClassValue и enter/finally/restore без создания Scope на каждом тике.
- Create ищет известные действия в соседних чанках вместо ~1800 запросов отдельных позиций; ближайшие сущности считываются один раз. Радиус, TTL и правила выбора владельца сохранены.
- Очистка служебных кэшей выполняется фоновым потоком. Выбрасывание предметов агрегируется одним владельцем в фоне, без таймера на каждый toss и без гонки счётчика.
- Отложенные снимки выполняются по реальным дедлайнам серверных тиков; TickTask не использовался как настоящий таймер и заменён отдельной очередью.

Чтение живого мира, вызовы сохранения сущностей/BlockEntity/компонентов модов, снятие содержимого слотов и применение откатов остаются на серверном потоке. Это необходимо для согласованных снимков. Само снятие большого NBT всё ещё может стоить заметного времени; нулевую нагрузку и конкретный рост TPS без измерения на сервере гарантировать нельзя.

### Дополнительный проход по нагрузке тиков, 6 октября

- Изменения блоков без NBT сразу передаются в очередь событий: дополнительная CPU-задача и второй переход между очередями не нужны. Формирование LogEntry и кодирование состояний остаются фоновыми; основной поток передаёт небольшой неизменяемый объект события. Типы действий и поля записи сохранены.
- Вызовы setBlock, уже исключённые правилами ванильной симуляции, отсекаются до обращения к AuthCore. Для захватываемых событий авторизация проверяется как прежде, без кэширования разрешения.
- Проверки взаимодействий повторно используют BlockEntity и оценку размера исходного снимка; неизменившийся блок без NBT не создаёт фоновой задачи. Частота снятия снимков и окно наблюдения сохранены.
- Контейнерный fallback повторно использует считанные состояние и BlockEntity. Семантика двойных сундуков и поиск сторонних capability не меняются.
- В записи используются массивы отложенных тегов вместо EnumMap: на снимок создаётся меньше служебных объектов, при передаче в очередь контейнер ссылок по-прежнему копируется.
- История каждого игрока хранит консервативные пространственные границы. Далёкие истории пропускаются до перебора до 64 действий; TTL, порядок, оценка уверенности и выбор автора не меняются. Границы обновляются с амортизированной постоянной стоимостью; они могут включить лишнего кандидата, но не исключают подходящего.
- При отсутствии откатов и подготовки планов обработчик тика сразу возвращается.

Регрессионные проверки сравнивают пространственный отбор с полным перебором, включая телепортации, отрицательные координаты, границы радиуса и вытеснение старых действий. В модельном сценарии 128 разнесённых игроков просматриваются 64 действия вместо 8192; это число операций данного сценария, не измерение TPS реального сервера. Отдельно проверяются типы изменений блоков, изоляция очереди при замене снимков и все шесть полей NBT.

## Хранение

CPU → очередь событий → дедупликация → фоновая запись журнала → доставка ClickHouse. Все очереди ограничены числом элементов и оценкой памяти, включая обрабатываемые элементы. При переполнении подача ждёт свободного места; события больше не отбрасываются. Один снимок, превышающий лимит, обрабатывается отдельно.

Пакеты журнала записываются в `avilixlogger-spool/<идентификатор-настройки-БД>` с `force(true)` и публикацией файла после завершения записи. При недоступной БД пакет остаётся на диске и восстанавливается после перезапуска. Успешно доставленные файлы удаляются. Файл с повреждённой/незавершённой записью сохраняется для восстановления и сопровождается ошибкой в журнале сервера. Не удалять каталог spool при обновлении или переносе сервера.

Доставка ждёт подтверждения ClickHouse, использует стабильные ID и токены повторных пакетов. Для таблиц MergeTree включается `non_replicated_deduplication_window=1024`; нужны права ALTER, уже используемые модом для схемы. Параметры asyncInsert/waitForAsyncInsert сохранены для совместимости конфигов, но пакеты отправляются с `async_insert=0` из фонового потока. Повтор не увеличивает исходные счётчики предметов.

Это защита от штатного переполнения очередей и сбоев БД, а не обещание абсолютной сохранности при kill -9, отказе диска или питания: ещё не записанные в журнал снимки находятся в RAM. При отказе диска и заполненных буферах возникает backpressure, включая возможную задержку серверного потока; одновременно гарантировать ограниченную память, отсутствие ожидания и сохранение всех событий при бесконечной перегрузке невозможно. Дедупликация ClickHouse ограничена окном сервера, особенно если в те же таблицы пишут другие процессы.

## Откаты

Разбор текстового NBT выбранных блоков, сущностей и предметов перенесён в подготовку плана. Память разобранных тегов учитывается в лимите плана. Локальные резервные копии мира остаются отделёнными NBT-тегами, без цикла SNBT→парсинг. Сохранены проверка слотов, возврат резервных копий при неудаче и бюджет работы по тикам.

## Проверки и установка

`./gradlew build` включает тесты очередей и журнала, проверку миксинов и обфускации. Тестируются заполнение очереди без потери записей, порядок четырёх производителей, крупный снимок, остановка, счётчики drop, сроки отложенных снимков, подготовка NBT, недоступная БД, повтор после потерянного подтверждения и восстановление журнала. HTTP-тест проверяет одинаковые payload/token после частичного успеха записи feed/detail; это не полноценный тест реального сервера ClickHouse. Проверка обфускации контролирует имена полей дискового формата.

JAR заменяется при остановленном Minecraft-сервере. Для проверки реального выигрыша нужен Spark-профиль при сопоставимом онлайне/нагрузке и проверка действий/откатов на сервере с AvilixAuthCore и используемыми модами. Smoke-запуск с AE2 проверяет загрузку и миксины, но без AvilixAuthCore логирование в нём корректно отключено.
